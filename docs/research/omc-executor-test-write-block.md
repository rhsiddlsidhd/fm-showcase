# executor의 test 파일 쓰기 권한 차단 조사

> executor 에이전트는 test 파일에 대해 Read 외의 도구 권한을 구조·시스템적으로 갖지 않는다.

현재 상태: 부분 달성. `Edit`/`Write` 차단은 확인했고, `Bash` 우회는 알려진 틈으로 두고 폐쇄를 보류한다. (조사일 2026-10-20, Claude Code 2.1.304)

## 1. 규칙과 범위

`test-engineer`가 테스트를 쓰고 `executor`가 구현을 쓰는 분업을 파이프라인으로 돌려 본 결과, 역할 경계는 프롬프트 요청에 따라 지켜졌다. `test-engineer`는 "테스트를 작성해줘"라는 요청에서 구현 없이 Red에서 멈췄고, `executor`는 테스트를 읽고 구현 파일만 만들어 12개 테스트를 통과시켰다. 그러나 이 경계는 문서가 보장하는 것이 아니다. `test-engineer` 문서는 구현이 담당이 아니라면서(`역할`, `제약_사항`) TDD 항목에서는 통과시킬 최소 코드를 쓰라고 한다(`TDD_강제`). `executor` 문서의 "테스트 꼼수 금지"도 프롬프트 수준의 규칙일 뿐이다. 그래서 경계를 시스템으로 강제할 수단이 필요하다.

`Read`는 막지 않는다. `executor`가 구현하려면 테스트를 읽어야 하기 때문이다. 시험 중 가드가 `Read`까지 막았을 때 `executor`는 아무것도 하지 못하고 멈췄다. 시험에서 보호 대상으로 쓴 경로는 `*.test.ts`, `*.test.tsx`, `vite.config.ts`, `vitest.config.ts`이며, 이 범위가 적절한지는 아직 정해지지 않았다(5절).

## 2. 확인된 차단 수단

| 수단 | 결과 | 확인 방법 |
|---|---|---|
| 설정 파일의 `PreToolUse` 훅 | 서브에이전트 안의 도구 호출에서도 실행됨 | 실제 `executor` 호출, 훅 로그 |
| 훅 입력의 `agent_type` | `executor`는 `oh-my-claudecode:executor`, 메인 세션은 `null` | 실제 호출, 훅 로그 |
| `Edit` 거부 (`permissionDecision: "deny"`) | `executor`가 우회 없이 중단, 파일 해시 불변 | 실제 호출, `sha256sum` |
| `Read` 허용 | 막으면 `executor`가 구현을 못 함 | 실제 호출 (가드 설계 오류로 발견) |
| 세션 도중 설정 | 설정 직후 호출부터 적용됨 | 실제 호출 |
| 메인·`test-engineer`의 쓰기 허용 | `agent_type`으로 구분되어 통과 | 가짜 입력으로 가드 로직만 시험 (실제 호출 아님) |

## 3. 에이전트 단위로 쓸 수 없는 수단

| 수단 | 한계 |
|---|---|
| 에이전트 정의의 frontmatter `hooks` | 플러그인 서브에이전트(`executor`)에서는 무시됨 |
| `disallowedTools` | 도구 전체를 제거하며 경로별 지정은 안 됨 |
| `permissions.deny` | 세션 전체에 적용되어 `test-engineer`와 메인도 막힘 |

frontmatter `hooks`는 원래 해당 서브에이전트가 실행되는 동안에만 도는 훅을 에이전트 정의에 직접 넣는 기능이라 에이전트별 차단에 가장 맞는 수단이다. 그러나 `executor`는 oh-my-claudecode 플러그인이 제공하는 에이전트여서, 문서가 "보안상의 이유로" `hooks`, `mcpServers`, `permissionMode`를 로드할 때 무시한다고 명시한다. 그래서 이 조사에서는 프로젝트 설정 파일에 훅을 등록하고 스크립트가 `agent_type`을 직접 검사하는 방식으로 에이전트별 스코프를 대신했다. 문서는 대안으로 에이전트 파일을 `.claude/agents/`에 복사하면 `hooks`를 쓸 수 있다고 안내하지만, 복사본이 파이프라인이 부르는 `oh-my-claudecode:executor`를 대체하는지는 확인하지 못했다(5절).

근거는 `code.claude.com`의 hooks·sub-agents 문서이며 WebFetch로 원문을 확인했다. 단 길이 때문에 hooks 문서는 앞 100,000자(전체 273,449자), sub-agents 문서는 앞 100,000자(전체 109,506자)만 읽었다.

## 4. 알려진 틈: Bash 우회 (폐쇄 보류)

가드 정규식에 가짜 입력을 넣은 오프라인 시험에서 `sed -i`, `echo >`, `python -c`로 test 파일을 직접 쓰는 명령은 차단됐다. 반면 `python`에서 `glob`으로 경로를 간접 지정하는 경우와 파일명을 문자열로 쪼갠 경우는 통과했다. 조사 에이전트는 문서가 `Bash` 규칙을 보안 경계가 아니라고 명시하며 `python -c`류의 간접 쓰기는 막지 못한다고 보고했는데, 이 부분의 원문은 직접 확인하지 못했다.

실제 `executor`가 이 틈을 쓴 적은 없다. 실행한 시험은 두 번이다. 첫 번째는 `Read`가 잘못 막힌 상황이었고 프롬프트에 "막히면 다른 방법을 시도해도 돼"를 붙였지만, `executor`는 `sed`·`echo`로 우회하는 것을 동결 규칙을 피하는 일로 판단해 거부하고 멈췄다. 두 번째는 정상 요청에서 `Edit`이 거부된 상황이었고, 역시 `Bash`나 `Write`로 우회하지 않고 멈췄다. 우회를 명시적으로 지시한 시험은 자동 모드 분류기가 거부해서 실행되지 않았다. 두 시험 모두 "주석 한 줄 추가"라는 작업이어서, 구현이 막히거나 테스트가 틀려 `executor`가 테스트를 고칠 동기가 생기는 압박 상황은 시험하지 못했다.

이 틈은 지금 닫지 않는다. 관찰된 우회가 없는 상태에서 닫으면 근거 없는 설계가 되기 때문이다. **`executor`의 우회 시도가 한 번이라도 관찰되면 그때 닫는다.**

## 5. 열린 쟁점

- 동결 커밋을 둘지 여부 (미결)
  - 둔다면 커밋 주체: 별도 스크립트, 메인 세션, `test-engineer` 중 하나
  - 복구 방식: `executor` 종료 후 동결 커밋 기준으로 보호 경로를 되돌리는 안 (구현·시험 안 함)
- 보호 범위: 테스트 파일만 둘지, 설정(`vite.config.ts`)과 fixture까지 포함할지
- 테스트가 틀렸을 때의 탈출구: `executor`가 못 고치면 교착되므로 누가 어떤 절차로 고치는지 정해야 함
- `.claude/agents/`에 `executor` 정의를 복사해 frontmatter `hooks`를 쓰는 방식: 문서가 안내하지만 시험하지 않음
