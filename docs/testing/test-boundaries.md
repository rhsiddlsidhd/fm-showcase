# 테스트 경계

테스트 층마다 무엇을 진짜로 쓰고 무엇을 대역으로 바꾸는지, 어떤 동작을 어느 층에서 검증하는지 정한다.

층을 가르는 기준은 **무엇을 진짜로 쓰는가**다. 같은 동작을 여러 층에서 검증할지는 [`test-policy.md`](./test-policy.md#중복-검증-금지)를 따른다.

## Unit 경계

화면 없이 입력과 출력, 상태 전이만으로 판정되는 로직을 검증한다.

| 대상                               | 단위로 보는 이유                          |
| ---------------------------------- | ----------------------------------------- |
| 순수 함수 (검증, 변환, 계산, 정렬) | 입력과 출력만으로 판정된다                |
| 상태 전이에 분기가 있는 훅         | 화면 없이 상태 전이를 확인한다            |
| reducer, 상태 기계                 | 상태와 이벤트의 조합이 많아 표로 검증한다 |
| `api/` 모듈                        | 요청과 응답 변환을 화면 없이 확인한다     |

- `lib/`·`model/`(훅 포함)의 로직은 여기서 검증한다.
- 언제 그쪽으로 내리는지는 [`layers.md`](../architecture/layers.md#pages)를 따른다.
- 내리기 전의 단순한 로직은 이를 쓰는 동작 컴포넌트의 테스트가 확인한다.
- 렌더가 필요하면 Unit이 아니라 [Component 경계](#component-경계)다.

## Component 경계

관여하는 동작 컴포넌트가 하나인 행동을 검증한다.

### 컴포넌트 분류

`ui/`의 컴포넌트는 레이어와 관계없이 아래 둘 중 정확히 하나다. 표시 컴포넌트가 아니면 동작 컴포넌트다.

**표시 컴포넌트**. 테스트하지 않는다.

- 자기 상태가 없다.
- 받은 props를 그리거나, props 값에 따라 보여줄 것을 고르거나, 받은 콜백을 요소에 연결하기만 한다.
- 값 가공 로직(필터, 정렬, 계산, 포맷, 검증)을 직접 쓰지 않는다. `lib/`·`model/`의 순수 함수를 호출하는 것은 허용한다.

**동작 컴포넌트**. 테스트한다.

- 예: 상태 변경, 값 가공 로직, Context·스토어 읽기, 부수 효과, 데이터 요청. 닫힌 목록이 아니다.

페이지 컴포넌트는 `ui/`가 아니라 `pages/<슬라이스>/index.tsx`에 있고 이 분류 밖이다. 정의는 [`layers.md`](../architecture/layers.md#pages)에 있다.

### 대상과 범위

| 대상                  | 예                                              |
| --------------------- | ----------------------------------------------- |
| 입력과 제출           | 폼에 입력하고 제출하면 성공 메시지가 보인다     |
| 입력 검증 흐름        | 빈 값으로 제출하면 오류가 뜨고, 고치면 사라진다 |
| 목록의 조작           | 검색어를 입력하면 카드 목록이 줄어든다          |
| 서버 응답에 따른 화면 | 로딩 → 성공 / 실패 화면 전환                    |

- 렌더 범위 안의 표시 컴포넌트, 훅, `model/` 함수는 진짜로 쓴다. 대역 범위는 [의존성 격리 원칙](#의존성-격리-원칙)을 따른다.
- 동작 컴포넌트가 `<Link>`를 렌더만 하고 경로 이동을 검증하지 않으면 이 층이다. 필요하면 라우터 Provider로 감싼다.
- 관여하는 동작 컴포넌트가 둘 이상이거나 경로 이동을 검증하면 [Integration 경계](#integration-경계)다.

### 테스트하지 않는 것

| 대상                                    | 이유                                                                              |
| --------------------------------------- | --------------------------------------------------------------------------------- |
| 페이지 컴포넌트                         | 배치만 한다 ([`layers.md`](../architecture/layers.md#pages))                      |
| 표시 컴포넌트                           | 상태가 없고 그리기만 한다. 연결이 맞는지는 부모 동작 컴포넌트의 테스트가 확인한다 |
| `src/shared/ui/`의 shadcn 컴포넌트 자체 | 라이브러리가 보장한다. 얹은 조합은 이를 쓰는 동작 컴포넌트의 테스트에서 본다      |
| 스타일 (Tailwind 클래스)                | 시각 일치는 사용자가 원본과 비교해 PR `Test plan`에 남긴다 ([`ui`](../ui/README.md#작성-규칙)) |

## Integration 경계

한 행동에 관여하는 동작 컴포넌트가 둘 이상이거나 라우터로 경로를 이동하는 흐름을 검증한다.

| 경로               | 예                                                                   |
| ------------------ | -------------------------------------------------------------------- |
| 동작 컴포넌트 중첩 | `ProductList`가 자식 동작 컴포넌트 `FilterPanel`과 상태를 주고받는다 |
| 공유 상태          | 두 동작 컴포넌트가 같은 Context나 스토어를 읽고 쓴다                 |
| 라우터             | 목록에서 카드를 누르면 챌린지 라우트로 이동해 해당 화면이 보인다     |

- 렌더 범위 안의 동작 컴포넌트, 표시 컴포넌트, 훅, 상태, 라우터, `api/` 모듈은 진짜로 쓴다 ([의존성 격리 원칙](#의존성-격리-원칙)).
- 라우터를 쓰는 흐름은 페이지 컴포넌트를 거치지만 페이지 컴포넌트를 검증하는 것은 아니다.

## E2E 경계

jsdom이 잡지 못하는 것만 빌드된 앱을 실제 브라우저로 검증한다.

| E2E로 보는 것                                     | jsdom이 못 잡는 이유                  |
| ------------------------------------------------- | ------------------------------------- |
| 반응형 레이아웃                                   | jsdom은 레이아웃을 계산하지 않는다    |
| 키보드 포커스 이동, 포커스 트랩, Tab 순서         | jsdom의 포커스 모델은 단순화되어 있다 |
| 새로고침 후 상태와 딥링크                         | 빌드 결과물과 서버 설정이 필요하다    |
| 빌드 산출물이 실제로 동작하는가                   | 개발 서버와 빌드 결과가 다를 수 있다  |
| 브라우저 고유 동작 (`<dialog>`, 스크롤, 클립보드) | jsdom이 구현하지 않거나 다르다        |

- 빌드 산출물 확인은 슬라이스당 대표 흐름 하나로 한다.
- 픽셀 단위 시각 일치는 검증하지 않는다.

## 의존성 격리 원칙

- 대역은 비결정적이거나 jsdom에 없는 것에만 쓴다: HTTP, 시간, 난수, jsdom이 구현하지 않는 브라우저 API(`IntersectionObserver` 등).
- 예외는 Component의 `api/` 모듈 하나다. Component는 화면 동작만 검증하고 요청과 응답은 Unit이 맡는다. 이 차이가 Component와 Integration의 경계다.
- 그 밖의 협력 대상(`lib/`·`model/`의 함수, 같은 모듈 안의 함수)은 대역으로 바꾸지 않는다. 필요해 보이면 대상 분리를 먼저 검토한다.
- HTTP는 MSW로 고정한다.
- 모듈 대역(`vi.mock`)은 위 예외에만 쓴다.
- 브라우저 저장소는 jsdom의 것을 진짜로 쓴다.
- 대역으로 바꾼 시간과 브라우저 API에 기대는 동작은 E2E에서 진짜로 한 번 확인한다.
- 제3자 API 대역은 실제 응답을 확인한 근거(문서 링크나 확인 날짜)를 대역 옆에 남긴다.

층별로 대역으로 바꿀 수 있는 범위:

| 층          | 대역 가능                                     | 진짜로 쓴다                                         |
| ----------- | --------------------------------------------- | --------------------------------------------------- |
| Unit        | HTTP, 시간, 난수, jsdom에 없는 브라우저 API   | 대상, `lib/`·`model/`의 협력 함수                   |
| Component   | Unit의 범위, `api/` 모듈                      | 렌더 범위 안의 컴포넌트, 훅, 상태                   |
| Integration | Unit의 범위                                   | 렌더 범위 안의 컴포넌트, 훅, 상태, 라우터, `api/`   |
| E2E         | 제3자 외부 네트워크, 루트 `api/` 경로 (경로를 가로채 고정) | 브라우저, 라우터, 빌드 결과물                       |

### `api/` 계약

Component는 `api/`를 대역으로 바꾸므로, Unit과 Component가 서로 다른 가짜 값으로 각자 통과할 수 있다. 양쪽을 같은 값으로 묶어 이를 막는다.

- `api/` 함수는 실패를 throw하지 않고 성공과 실패의 유니온으로 반환한다. 실패가 타입에 드러나야 `typecheck`가 호출부를 확인한다.
- 반환값은 성공과 실패마다 fixture 하나로 둔다. Unit은 `api/`가 그 fixture를 반환하는지 확인하고, Component의 `vi.mock`은 그 fixture를 돌려준다.
- 호출 인자도 양쪽이 같은 값을 쓴다. Component는 동작 컴포넌트가 그 인자로 호출하는지, Unit은 그 인자가 기대한 HTTP 요청이 되는지 확인한다.

## 파일 배치

- 테스트 파일은 대상 파일 옆에 둔다.
- 슬라이스의 fixture와 MSW 핸들러는 그 슬라이스의 `api/`에 `fixtures.ts`, `handlers.ts`로 둔다. 슬라이스 공개 API로 내보내지 않는다.
- 여러 슬라이스가 쓰는 전역 준비 코드만 `src/shared/test/`에 둔다. 슬라이스 전용 타입을 쓰는 코드를 두면 `shared`가 `pages`를 import하게 된다.

## `scripts/` 적용 범위

`scripts/`는 화면이 없어 층이 Unit 하나다.

- [Unit 경계](#unit-경계)와 [의존성 격리 원칙](#의존성-격리-원칙)을 적용한다.
- Component, Integration, E2E, 컴포넌트 분류, [`api/` 계약](#api-계약)은 적용하지 않는다.
- [`test-policy.md`](./test-policy.md)는 그대로 적용한다.
- `scripts/features/git-hooks/`의 판정 로직도 대상이다.

## 루트 `api/` 적용 범위

루트 `api/`는 외부 API를 중계하는 Vercel Functions다([시스템 경계](../architecture/boundary.md#vercel-functions)). 슬라이스의 `api/` 세그먼트와 다르다.

- 화면이 없어 층이 Unit 하나다. 함수 핸들러를 직접 호출한다.
- 외부 API는 MSW로 고정한다.
- 요청받은 주소와 관계없이 정해 둔 외부 주소만 호출하는지 검증한다.
- 키가 필요한 외부 API는 키를 붙여 호출하고, 응답에 키가 들어가지 않는지 검증한다.
- 외부 API가 실패하면 실패 응답을 돌려주는지 검증한다.
- E2E는 `vite preview`로 띄워 함수가 실행되지 않는다. 함수는 Unit이 검증하므로 E2E에서는 루트 `api/` 경로를 가로채 고정 응답을 준다.
