# 테스트 경계

검증하려는 계약과 실제 연결 범위를 기준으로 테스트 층의 경계를 정의한다.

동일 동작의 층별 검증 범위와 중복 여부는 [`test-policy.md`](./test-policy.md#층별-검증)를 따른다.

## 공통 분류 원칙

테스트 층은 검증 목적과 실제 연결 범위를 함께 고려하여 분류한다.

- **검증 목적:** 테스트 실패가 어떤 계약 위반을 의미하는지 확인한다.
- **연결 범위:** 검증 대상과 실제로 연결한 협력 관계를 확인한다.
- **분류 기준:** 대상의 종류, 파일 경로, 사용 도구, 렌더링 여부만으로 테스트 층을 결정하지 않는다.
- **협력 관계:** 여러 구성 요소가 실행된다는 사실과 구성 요소 사이의 협력을 검증한다는 것은 구분한다.
- **실행 환경:** 실제 브라우저 사용 여부는 테스트 층과 별개로 판단한다.

### 의존성 격리

검증 목적에 필요한 협력 관계는 실제로 연결한다. 통제할 수 없는 외부 서비스, 비결정적 동작 또는 외부 부작용은 검증 목적에 포함되지 않는 한 격리하는 것을 기본으로 한다.

의존성의 연결과 격리가 충돌하면 다음 순서로 판단한다.

1. **필수성:** 해당 의존성이 검증하려는 계약에 필요한가?
2. **연결성:** 대역으로 대체하면 검증하려는 협력 관계가 사라지는가?
3. **결정성:** 실제 연결을 유지하면서 실행 환경을 통제할 수 있는가?
4. **대체 가능성:** 격리해도 검증하려는 계약이 유지되는가?
5. **잔여 위험:** 격리로 인해 검증하지 못한 연결을 별도로 확인해야 하는가?

- 실행 속도나 편의성만을 이유로 필수 협력 관계를 대역으로 대체하지 않는다.
- 비결정적이거나 외부 부작용이 있는 의존성은 검증 목적에 따라 통제한다.
- 대역은 신뢰할 수 있는 계약을 근거로 필요한 입력, 출력, 오류 조건을 재현해야 한다.
- 실제 연결이 불가능하면 검증 가능한 범위와 남는 위험을 구분한다.

## Unit 경계

선택한 대상의 계약을 격리하여 검증한다.

| 대상 | 검증할 계약 |
| --- | --- |
| 순수 함수 | 입력에 따른 출력 |
| Reducer, 상태 기계 | 입력이나 이벤트에 따른 상태 전이 |
| 훅, 컴포넌트 | 격리된 대상의 동작과 렌더 결과 |
| 데이터 변환 모듈 | 데이터 변환과 오류 처리 |
| 기타 애플리케이션 모듈 | 대상이 제공하는 독립적인 계약 |

Unit의 검증 범위는 선택한 대상의 계약이며, 다른 구성 요소와의 협력 관계 자체는 포함하지 않는다.

## Integration 경계

둘 이상의 구성 요소 사이에서 발생하는 실제 협력 관계를 검증한다.

| 연결 범위 | 검증할 계약 |
| --- | --- |
| UI와 상태 관리 | 상태 변경과 화면 반영 |
| UI와 라우터 | 탐색, URL 변경, 상태 복원 |
| UI와 데이터 처리 | 데이터 상태에 따른 화면 전환 |
| 여러 애플리케이션 모듈 | 모듈 간 데이터 전달과 처리 결과 |
| 애플리케이션과 내부 서비스 | 요청 전달, 응답 처리, 오류 전파 |
| 애플리케이션과 외부 API | 요청 구성, 응답 처리, 오류 전파 |

Integration의 검증 범위는 구성 요소 사이의 상호작용과 그 결과다.

외부 API 자체는 통제할 수 없는 의존성이라 [의존성 격리](#의존성-격리) 원칙에 따라 기본적으로 대역으로 격리하고, 애플리케이션이 요청을 구성하고 응답과 오류를 처리하는 계약만 검증한다. 브라우저 직접 호출과 Vercel Functions 중계 중 어느 경로를 거치든 같은 경계가 적용되며, 경로 선택 기준은 [`boundary.md`](../architecture/boundary.md#외부-api)를 따른다.

## E2E 경계

실행 중인 애플리케이션에서 사용자 흐름과 시스템 연결이 올바르게 작동하는지 검증한다.

| 검증 범위 | 검증할 계약 |
| --- | --- |
| 주요 사용자 흐름 | 사용자 행동부터 최종 결과까지의 연결 |
| 페이지 간 탐색 | 실제 라우팅과 탐색 상태 유지 |
| 새로고침과 직접 접근 | 상태 복원과 딥링크 동작 |
| 애플리케이션 실행 환경 | 빌드 결과물과 실행 환경의 동작 |
| 브라우저와 애플리케이션 | 브라우저 기능을 포함한 사용자 흐름 |

E2E의 검증 범위는 개별 구성 요소의 계약이 아니라 실행 환경을 포함한 사용자 흐름과 시스템 연결이다.

## 컴포넌트 테스트

컴포넌트 테스트는 렌더링 대상을 나타내며, 독립적인 테스트 층으로 취급하지 않는다.

| 검증 범위 | 분류 |
| --- | --- |
| 격리된 컴포넌트의 계약 | Unit |
| 여러 구성 요소의 협력 관계 | Integration |
| 실행 중인 애플리케이션의 사용자 흐름 | E2E |

컴포넌트에서 검증할 수 있는 계약에는 콘텐츠, 접근성 속성, 조건부 표시, 사용자 조작 결과 등이 포함된다.

외부 UI 라이브러리의 내부 계약보다 프로젝트에서 구성하거나 변경한 동작을 검증 대상으로 삼는다.

## 실제 브라우저 검증

실제 브라우저 검증은 테스트 층이 아니라 실행 환경의 선택이다.

| 검증 대상 | 브라우저가 필요한 이유 |
| --- | --- |
| 반응형 레이아웃 | 실제 레이아웃과 뷰포트 계산 |
| 키보드 탐색과 포커스 | 브라우저의 포커스 및 탐색 동작 |
| 스크롤과 위치 계산 | 실제 렌더링 및 스크롤 처리 |
| 브라우저 고유 API | 실행 환경에 따른 동작 차이 |
| 시각적 결과 | 실제 스타일 계산과 렌더링 결과 |

애니메이션의 진행 과정(중간 프레임의 보간값, easing, timing)은 자동 검증 대상이 아니다. 애니메이션이 유발하는 최종 상태나 discrete한 분기(클래스 토글, DOM 존재 여부, 움직임 줄이기 분기, 완료 후 콜백)만 검증 목적과 연결 범위에 따라 Unit, Integration 또는 E2E로 분류한다.

실제 브라우저를 사용하더라도 검증 목적과 연결 범위에 따라 Unit, Integration 또는 E2E로 분류한다.
