# 테스트 정책

모든 층의 테스트에 공통으로 적용하는 기준을 정한다. 층마다 무엇을 검증하는지는 [`test-boundaries.md`](./test-boundaries.md)에 있다.

## 테스트 대상 선정 기준

- 요구사항에 없는 구현 세부는 테스트하지 않는다.

## 중복 검증 금지

- 같은 동작은 한 층에서만 검증하고, 가장 아래 층에서 확인할 수 있으면 거기서 끝낸다. 아래는 겹쳐도 두는 예외다.
  - 로직을 `lib/`·`model/`로 내린 뒤에도 그 로직을 쓰는 컨테이너 컴포넌트의 테스트는 대표 경로 하나를 확인한다. 연결이 맞는지는 Unit이 잡지 못한다.
  - E2E의 대표 흐름은 하위 층과 겹쳐도 둔다. 확인하는 것은 동작이 아니라 빌드 산출물이다 ([E2E 경계](./test-boundaries.md#e2e-경계)).
  - 대역으로 바꾼 동작의 E2E 재확인 ([의존성 격리 원칙](./test-boundaries.md#의존성-격리-원칙)).

## 완료 기준

- 요구사항마다 대응하는 테스트가 있다. 단 [`test-boundaries.md`](./test-boundaries.md#테스트하지-않는-것)에만 해당하는 요구사항은 이 저장소의 예외로, 테스트가 없어도 완료로 본다.
- 해당 챌린지에 있는 오류, 빈 상태, 로딩 상태를 모두 검증한다.
