# 보고 규칙

Discord로 나가는 보고서의 규칙이다. 보고를 만드는 쪽은 둘이고(대화형 세션의 스킬, 이벤트로 도는 워크플로) 둘 다 이 디렉토리를 따른다.

이 README는 인덱스다. 서식 본문은 아래 문서에 둔다.

## 문서

| 문서                         | 읽는 조건                             | 다루는 내용                                                    |
| ---------------------------- | ------------------------------------- | -------------------------------------------------------------- |
| [`formats.md`](./formats.md) | Discord로 보낼 본문을 만들거나 고칠 때 | 보고서 종류와 이모지, 제목 줄, 본문 모양, 종류별 항목과 순서 |

## 통로

보고가 Discord에 닿는 경로는 둘이고, 만드는 쪽에 따라 하나로 정해진다.

| 만드는 쪽     | 통로                                                                           |
| ------------- | ------------------------------------------------------------------------------ |
| 대화형 세션   | MCP ([`discord-message`](../../.claude/skills/discord-message/SKILL.md))       |
| 이벤트 구동   | Discord webhook                                                                |

- 세션에서는 webhook, `curl`, 직접 만든 스크립트로 보내지 않는다. MCP 전송이 실패하면 보내지 못했다고 알리고 멈춘다.
- 워크플로에서는 MCP를 쓰지 않는다. 런너에 Discord MCP 플러그인이 없다.

세션의 우회 금지와 워크플로의 webhook 사용은 서로 예외가 아니다. 세션에서 우회를 허용하면 전송 실패가 조용히 묻히고, 사람이 보낸 보고와 자동 보고를 구분할 근거도 사라진다.

## 비밀값

- webhook URL은 저장소 Secrets에만 둔다. 프롬프트, LLM이 쓸 수 있는 도구, LLM의 출력에 넣지 않는다.
- LLM은 본문만 돌려주고 전송은 다음 스텝이 한다. 모델 출력이 유출 경로가 되지 않게 하려면 모델이 주소를 모르는 편이 낫다.
