# Pull Request 규칙

전역 `GIT.md`의 Pull Request 규칙 중 아래 항목을 덮어쓴다. 나머지는 전역 규칙을 따른다.

## 언어

- 제목은 `{prefix}: {한국어 메시지}` 형식으로 쓴다. `prefix`는 전역 `GIT.md`의 분류를 영어 그대로 쓴다.
- 제목은 50자 내외로 쓴다.
- 본문은 한국어로 쓴다. 섹션 제목은 템플릿의 영어 그대로 둔다.
- 명령어, 경로, 식별자는 번역하지 않고 그대로 쓴다.

## 내용 범위

PR 본문은 리뷰어가 merge를 판단하는 데 필요한 것만 쓴다.

- `Summary`: 왜 필요한 변경인지와 결과를 쓴다. 변경 파일 목록처럼 diff에서 보이는 내용은 쓰지 않는다.
- `Issue`: merge되면 해당 Issue의 완료 조건이 전부 충족될 때만 `Closes #N`을 쓴다. merge가 곧 완료 판정이고, 닫힘이 완료 기록의 근거이기 때문이다.
  - 일부만 충족하면 `Refs #N`을 쓴다.
  - 여러 PR로 나눈 Issue는 앞선 PR 결과까지 합쳐 판단하므로 마지막 PR에만 `Closes`를 쓴다.
  - merge 뒤에야 확인할 수 있는 조건이 남으면 `Refs #N`을 쓰고, 확인한 뒤 수동으로 닫는다.
  - 상위 묶음 Issue는 적지 않는다. 자기 완료 조건을 확인한 뒤 따로 닫는다.
- `Test plan`: 실제로 실행한 명령과 결과를 쓴다.

## 작성 방식

- 섹션 구조는 `.github/pull_request_template.md`를 따른다.
- 본문을 쓰기 전에 `format-fit` 스킬을 사용한다. 이 스킬은 내용의 구조에 맞는 서식을 고르며, 기본값은 산문이다.
- `format-fit`은 서식만 정한다. 무엇을 담을지는 `내용 범위`가 정한다.
- 섹션 안의 서식은 스킬 판정을 따른다. 인과가 있는 설명은 불릿으로 쪼개지 않고 문장으로 쓴다.
