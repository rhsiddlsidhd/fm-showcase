# Commit 규칙

전역 `GIT.md`의 Commit 규칙에 아래 항목을 더한다.

## Issue 닫기

- 커밋 메시지에 Issue를 닫는 키워드를 쓰지 않는다. 작업 브랜치 커밋은 merge commit으로 기본 브랜치에 그대로 들어가므로, 완료 조건을 다 채우기 전에 Issue가 닫힐 수 있다. Issue는 [`branch.md`](./branch.md)의 Issue 브랜치로 닫는다.

## 테스트 선행 증거

- 테스트 커밋은 그 테스트가 다루는 요구사항의 구현 커밋보다 먼저 만든다. 각 커밋은 같은 요구사항 범위를 다뤄야 순서가 증거가 된다.
- [회귀 테스트](../testing/test-policy.md#회귀-테스트)의 테스트 커밋에는 짝이 되는 구현 커밋이 없다. 커밋 메시지에 회귀 테스트임을 드러낸다.
- 구현 커밋까지 만든 뒤에 push한다. CI는 push된 최신 커밋을 검증한다.
