# 설계안 규칙

설계 문서를 어떻게 쓰는지 정한다. 대상은 도메인 설계안(`.sdd/`)과 결정 기록(`adr/`)이다. 화면을 설계할 때 무엇을 정할지는 [`ui/`](../ui/README.md)에 있다.

도메인은 페이지 슬라이스 하나다. 한 슬라이스의 라우트는 모두 한 도메인이다.

| 문서 | 읽는 조건 | 다루는 내용 |
| --- | --- | --- |
| [`requirements.md`](requirements.md) | 도메인의 요구사항서를 만들거나 고칠 때. PR에 요구사항과 테스트의 대응을 쓸 때 | 요구사항서의 섹션, 기능 요구사항 작성 기준, ID 규칙 |

## 산출 위치

설계안은 `.sdd/<슬라이스>/`에 둔다.

- 슬라이스 이름은 설계를 시작할 때 정한다.
- `.sdd/`는 구현 전 작업 자료라서 저장소에 남기지 않는다.
- 새 worktree에는 `.sdd/`가 없다. 구현 세션에는 메인 체크아웃의 경로를 직접 알려준다.

## 작성 규칙

- Issue, 과제 원문, 원본 디자인으로 답이 나오지 않는 판단은 지어내지 않는다. `(미결정)`으로 두고 사용자에게 묻는다.
- 구현은 설계안에 `(미결정)`이 없을 때 시작한다.
- 구현에 영향을 준 판단은 PR 본문에 옮긴다. `.sdd/`는 저장소에 남지 않아서 PR이 판단의 근거가 된다.
