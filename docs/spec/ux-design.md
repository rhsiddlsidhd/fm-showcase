# 화면 설계 문서

화면 설계 문서는 도메인의 화면 배치, 입력에 대한 반응, 움직임을 구현 전에 정한 설계안이다. 도메인마다 `.sdd/<슬라이스>/ux-design.md`에 둔다.

모든 도메인이 따르는 화면 규칙은 [`docs/ui/`](../ui/README.md)에 있다. 이 문서는 그 규칙을 도메인에 적용한 결과만 쓴다.

## 섹션

아래 순서로 쓴다. 내용이 없는 섹션은 `없음`으로 쓴다.

| 섹션 | 기재 내용 |
| --- | --- |
| 정적 자산 | [`static-assets.md`](../ui/static-assets.md) 규칙을 적용한 결과. 표 `원본 자산 \| 저장 경로 \| 사용 화면`. 화면 ID로 참조하므로 화면 목록보다 먼저 쓴다 |
| 화면 목록과 사용자 흐름 | 표 `화면 ID \| 화면 이름 \| 목적 \| 경로 진입 조건 \| 경로 이탈 조건`. ID는 `S-01`부터 |
| 화면별 와이어프레임 | 화면 ID마다 원본 링크, 배치와 계층, 화면 폭별 차이, 기본·로딩·빈·오류 상태의 배치·표현·문구 |
| 컴포넌트 선택 | 주요 UI 요소별 검토한 shadcn/ui 후보, 선택한 컴포넌트와 위치. 직접 만드는 경우 그 근거 |
| 입력과 상태 변화 | 입력 검증과 사용자 조작에 따른 조건·상태 전이. 화면 표현은 와이어프레임의 해당 상태를 참조 |
| 인터랙션과 애니메이션 | 표 `대상 \| 트리거 \| 목적·전달 정보 \| 등장 애니메이션 (초기 → 표시) \| 사라질 때 애니메이션 (표시 → 제거) \| 애니메이션 속성 \| 지속 시간·이징 \| 재실행·취소 동작 \| 애니메이션 동작 줄이기 설정 시 표현` |
| 접근성 | 포커스를 옮길 위치, 화면 낭독기로 알릴 값, 애니메이션 외 사용자 설정에 따라 달라지는 표현과 그 대체. 애니메이션 동작 줄이기 설정에 따른 표현은 인터랙션과 애니메이션 표에 쓴다 |

## 화면 목록과 사용자 흐름

경로 진입·이탈 조건에는 도메인 화면과 앱 경로 사이의 이동을 적는다. 같은 화면 안에서 검색 결과·오류 등 상태가 바뀌는 일은 이 표의 이탈로 쓰지 않는다.

## 화면별 와이어프레임

와이어프레임에는 각 상태가 화면에 나타나는 배치·표현·문구를 적는다. 제공된 UI 구현 파일을 바탕으로 설계안을 역으로 정리할 때는 코드에서 직접 확인한 배치·상태·문구를 `구현 관찰`로 기록하고, 관찰한 경로를 함께 적는다. 구현 코드가 드러내지 않는 의도나 이유는 추측하지 않는다.

## 컴포넌트 선택

표 `화면 ID \| UI 요소 \| 검토한 shadcn/ui 후보 \| 선택한 컴포넌트 \| 코드 위치 \| 선택 근거`로 작성한다.

검토한 후보에는 프로젝트에 이미 있는 부품과 공식 목록·레지스트리에서 실제로 확인한 부품만 기록한다. 선택 근거에는 공식 문서·레지스트리 링크와 UI 요구에 맞춰 확인한 실제 구성·API를 적는다. 도구 이름은 적지 않는다. 코드 위치에는 저장소 루트 기준 전체 경로를 적고, 각 경로에 `현행:` 또는 `예정:`을 붙여 현재 존재 여부를 나타낸다. 후보 탐색이나 적합성 판단이 끝나지 않았으면 [`설계안 작성 규칙`](README.md#작성-규칙)에 따라 최종 선택과 코드 위치를 `(미결정)`으로 둔다. 직접 제작은 [컴포넌트 규칙](../ui/component.md)의 기준을 충족할 때만 선택하고 근거를 쓴다.

각 행은 하나의 UI 역할과 하나의 선택을 다룬다. 입력·후보 목록·제출 버튼처럼 후보나 선택이 다른 요소는 행을 나눈다. 공식 후보는 실제 구성과 API 중 해당 UI 요구사항에 필요한 부분을 확인하고, 선택 근거에 그 적합성 또는 미결정 사유를 쓴다. 서로 다른 UI 역할을 묶어 선택 상태가 모호해지게 쓰지 않는다.

## 입력과 상태 변화

입력과 상태 변화에는 조작, 조건, 전이를 적고 화면 표현은 반복하지 않는다. 필요한 상태 표현은 와이어프레임의 해당 상태를 가리킨다.

## 인터랙션과 애니메이션

표 `대상 \| 트리거 \| 목적·전달 정보 \| 등장 애니메이션 (초기 → 표시) \| 사라질 때 애니메이션 (표시 → 제거) \| 애니메이션 속성 \| 지속 시간·이징 \| 재실행·취소 동작 \| 애니메이션 동작 줄이기 설정 시 표현`으로 작성한다. 애니메이션이 없으면 해당 열에 `없음`으로 쓴다.

목적·전달 정보에는 장식, 상태 표시 등 해당 움직임이 하는 역할을 적는다. 애니메이션 동작 줄이기 설정 시 표현에는 애니메이션을 줄이거나 끈 뒤에도 유지해야 하는 정보·피드백과 그 표현을 적는다. 움직임 자체가 필수라고 판단하면 그 이유를 적는다.

## 작성 기준

- 원본에서 분석한 문구, 배치, 상태는 구체적으로 쓴다.
- 디자인 토큰이 필요한 자리는 그 이름으로 가리킨다. 값은 쓰지 않는다([작성 규칙](../ui/README.md#작성-규칙)). 구현 세션이 어느 값을 어디에 쓸지 추측하지 않게 하기 위해서다.
- 정적 자산은 경로만 정하고 실제 파일을 두지 않는다. 복사는 구현 단계에서 한다([static-assets.md](../ui/static-assets.md)).
- 원본 링크는 원본이 있으면 연결하고, 없으면 `없음`으로 쓴다. 원본 파일은 두지 않는다([산출 위치](../ui/README.md#산출-위치)).
- 기존 UI 구현을 바탕으로 역설계할 때는 코드에서 확인한 현재 동작을 `구현 관찰`로 기록하고 해당 경로를 적는다. 코드가 드러내지 않는 의도나 이유를 추측하지 않는다.
- 화면 폭별 차이는 경계 이름으로 쓴다([`responsive.md`](../ui/responsive.md)).
- 화면에 없는 상태(로딩, 빈 상태, 오류)는 `없음`으로 쓴다. 빠뜨린 것과 구분하기 위해서다.
- 애니메이션을 적용하지 않으면 인터랙션과 애니메이션 섹션에 그 결정을 쓴다.
- 움직이는 속성은 [`animation.md`](../ui/animation.md#성능)의 허용 속성에서 고른다.
- 상태와 움직임마다 [검증 문서](verification.md)에 시나리오가 있어야 한다.
