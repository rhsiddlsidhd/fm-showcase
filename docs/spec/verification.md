# 검증 문서

검증 문서는 요구사항을 무엇으로, 어떤 시나리오로 확인할지 구현 전에 정한 설계안이다. 도메인마다 `.sdd/<슬라이스>/verification.md`에 두고, [요구사항서](requirements.md)의 ID를 참조한다.

테스트를 어느 층에 쓰고 어떻게 쓰는지는 [`docs/testing/`](../testing/README.md)이 정한다. 이 문서는 그 기준을 도메인에 적용한 결과만 쓴다.

## 섹션

아래 순서로 쓴다. 내용이 없는 섹션은 `없음`으로 쓴다.

| 섹션 | 쓰는 것 |
| --- | --- |
| 검증 범위 | 대상 요구사항 ID와 품질 요구사항 |
| 요구사항별 검증 방법 | 표 `ID \| 방법 \| 기대 결과 출처`. 방법은 테스트 층이나 사람 확인 |
| 검증 시나리오 | 표 `ID \| 종류 \| 해 볼 것 \| 기대 결과 \| 방법` |
| 환경과 테스트 데이터 | 시나리오에 필요한 fixture, 대역, 사전 조건 |
| 출시 승인 기준 | 이 도메인에서 사람이 추가로 확인할 항목 |

- 출시 승인 기준에 CI와 `main` 보호는 쓰지 않는다. 설정이 이미 강제한다.

## 검증 시나리오

- 종류는 `정상 | 실패 | 경계` 중 하나다.
- 요구사항 ID마다 시나리오가 하나 이상 있다.
- 자동 테스트 대상인 시나리오 한 행은 테스트 하나가 된다. 테스트를 먼저 쓸 때 이 행에서 시작한다.
- 자동 테스트의 방법에는 [`test-boundaries.md`](../testing/test-boundaries.md)로 고른 층을 쓴다. 컴포넌트 설계 전이라 정할 수 없으면 `(미결정)`으로 둔다.
- 기대 결과는 요구사항이나 과제 원문에서 가져온다. 구현 결과로 채우지 않는다([작성 규칙](../testing/test-policy.md#작성-규칙)).
- 슬라이스에 있는 로딩, 빈 상태, 오류 화면마다 시나리오를 쓴다([완료 기준](../testing/test-policy.md#완료-기준)).
- 애니메이션이 있는 동작은 일반 모션과 움직임 줄이기 설정의 시나리오를 각각 쓴다. 움직임 줄이기에서 무엇이 남는지는 [`animation.md`](../ui/animation.md#움직임-줄이기)를 따른다.
- [테스트하지 않는 것](../testing/test-boundaries.md#테스트하지-않는-것)에만 해당하는 요구사항은 요구사항별 검증 방법과 검증 시나리오의 방법에 사람 확인과 그 근거 링크를 쓴다. 이 시나리오는 자동 테스트로 만들지 않는다.
