# 검증 문서

검증 문서는 요구사항을 무엇으로, 어떤 시나리오로 확인할지 구현 전에 정한 설계안이다. 도메인마다 `.sdd/<슬라이스>/verification.md`에 두고, [요구사항서](requirements.md)의 ID를 참조한다.

테스트를 어느 층에 쓰고 어떻게 쓰는지는 [`docs/testing/`](../testing/README.md)이 정한다. 이 문서는 그 기준을 도메인에 적용한 결과만 쓴다.

## 섹션

아래 순서로 쓴다. 내용이 없는 섹션은 `없음`으로 쓴다.

| 섹션 | 쓰는 것 |
| --- | --- |
| 검증 범위 | 대상 요구사항 ID와 품질 요구사항 |
| 요구사항별 검증 방법 | 표 `ID \| 방법 \| 기대 결과 출처`. 방법은 테스트 층이나 사람 확인 |
| 검증 시나리오 | 표 `ID \| 종류 \| 해 볼 것 \| 기대 결과 \| 방법` |
| 환경과 테스트 데이터 | 시나리오에 필요한 실행 환경(jsdom·실제 브라우저 등), fixture, 대역, 사전 조건 |
| 출시 승인 기준 | 이 도메인에서 사람이 추가로 확인할 항목 |

- 출시 승인 기준에 CI와 `main` 보호는 쓰지 않는다. 설정이 이미 강제한다.

## 검증 시나리오

- 종류는 `정상 | 실패 | 경계` 중 하나다.
- 요구사항 ID마다 시나리오가 하나 이상 있다.
- 자동 테스트 시나리오에서 테스트를 설계한다. 하나의 테스트가 여러 시나리오를 확인하거나 매개변수화할 수 있다.
- 자동 테스트의 방법에는 [`test-boundaries.md`](../testing/test-boundaries.md)로 고른 층을 쓴다. 검증할 연결 범위가 정해지지 않아 층을 고를 수 없으면 `(미결정)`으로 둔다.
- 기대 결과는 요구사항이나 과제 원문에서 가져온다. 구현 결과로 채우지 않는다([작성 규칙](../testing/test-policy.md#작성-규칙)).
- 요구사항에 포함되고 실제 도달 가능한 로딩, 빈 상태, 오류 화면에 시나리오를 쓴다([완료 기준](../testing/test-policy.md#완료-기준)).
- 사용자 설정이나 실행 환경에 따라 동작이 갈리면 갈래마다 시나리오를 쓴다(예: 움직임 줄이기, 투명도 줄이기, 화면 폭 경계, 다크 모드). 갈래별로 무엇이 달라지는지는 그 갈래를 정한 [`docs/ui/`](../ui/README.md) 문서를 따른다.
- 자동화가 적합하지 않은 요구사항은 검증 방법에 사람 확인과 그 근거를 쓴다.
- 이번 작업에서 쓸 코드 밖의 원인으로 이미 충족될 것이 보이는 시나리오는 방법 칸에 층과 함께 `회귀`와 그 원인을 쓴다(예: `E2E, 회귀(메뉴 부품의 기본 동작)`, `E2E, 회귀(시각 표현 작업에서 구현)`). 판정 기준은 [회귀 테스트](../testing/test-policy.md#회귀-테스트)를 따른다. 구현 계획이 이 표시로 테스트 선행 대상과 회귀 대상을 나눈다.
