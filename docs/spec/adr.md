# 결정 기록 (ADR)

확정한 결정과 그 이유를 루트 `adr/`에 쌓는다. `docs/`는 현재 기준을, ADR은 고치지 않는 기록을 담는다.

## 쓰는 조건

- 사용자가 확정했고, 대안을 둘 이상 비교한 결정만 쓴다.
- 작업 중 초안과 검토 메모는 `.sdd/`에 둔다.

## 파일

- `adr/NNNN-<카테고리>-<선택 항목>.md`. 카테고리와 선택 항목은 영어 kebab-case로 쓴다. 번호는 `0001`부터 매기고 다시 쓰지 않는다. 링크가 다른 결정을 가리키게 된다.
- 카테고리는 자유롭게 정한다. 기존 ADR에 같은 뜻의 카테고리가 있으면 그 표기를 그대로 쓴다.
- 한 파일에 결정 하나만 쓴다.

## 템플릿

```markdown
# NNNN. 〈카테고리〉. 〈선택 항목〉

## Status

채택

## Context

〈결정이 필요했던 문제와, 결정이 기대는 전제〉 (출처: Issue #N / PR #N / 사용자 확인)

## Decision

- 〈결정 한 줄. "~한다"로 끝나는 규칙 문장〉

- 〈상황〉에서 〈문제〉를 해결해야 했다.
  〈선택 항목〉을 택하고 〈대안 A〉, 〈대안 B〉는 택하지 않았다.
  〈얻는 것〉을 얻기 위해서이며, 〈감수하는 것〉을 받아들인다.

## Consequences

| 선택지            | 얻는 것 | 잃는 것 |
| ----------------- | ------- | ------- |
| **〈선택 항목〉** | 〈…〉   | 〈…〉   |
| 〈대안 A〉        | 〈…〉   | 〈…〉   |
```

## 섹션

순서대로 쓴다. 분량은 권장 범위다. 상한을 넘으면 결정이 둘인지 먼저 확인하고 나눈다.

| 섹션 | 쓰는 것 | 하한 | 상한 |
| --- | --- | --- | --- |
| Status | `채택 \| 대체됨 (NNNN)` 중 하나 | 1줄 | 1줄 |
| Context | 결정이 필요했던 문제, 결정이 기대는 전제, 출처 | 1문장 | 3문장 |
| Decision | 결정 한 줄과 Y-statement 세 문장. Y-statement는 템플릿의 틀을 그대로 쓴다 | 4문장 | 4문장 |
| Consequences | 트레이드오프 표. 채택한 선택지 1행은 `**`로 감싸고, 그 아래 대안 행을 둔다 | 2행 | 4행 |

- Y-statement의 선택 항목과 대안 이름은 표의 행 이름과 같게 쓴다. `**`는 빼고 비교한다.
- Y-statement의 "얻는 것"과 "감수하는 것"은 채택 행의 두 칸과 같게 쓴다.
- Consequences의 칸은 명사구로 쓴다(예: `데이터 일관성 보장`, `수평적 확장 어려움`). 문장으로 설명하지 않는다.
- 한 칸에 항목이 여럿이면 `<br>`로 나눈다. 칸마다 1~3개.
- 채택 행의 "잃는 것"을 채울 수 없으면 비우지 않고 [`(미결정)`](README.md#작성-규칙)으로 두고 사용자에게 묻는다.
- 대안과 근거는 출처(Issue, PR, 사용자 확인)가 있는 것만 쓴다. 없으면 `(미결정)`으로 둔다.

## 변경

- 본문은 고치지 않는다. 결정이 바뀌면 새 ADR을 쓰고 옛 ADR은 상태만 `대체됨 (NNNN)`으로 바꾼다.
- 예외: 템플릿이 바뀌어 형식만 맞출 때는 결정 내용을 바꾸지 않는 범위에서 본문과 파일 이름을 고친다.
- 결정에서 나온 `docs/` 규칙은 그 ADR을 링크한다. 대안 비교를 `docs/`에 다시 쓰지 않는다.
