# 기능 설계서

기능 설계서는 요구사항을 어떤 흐름과 규칙으로 동작시킬지 구현 전에 정한 설계안이다. 도메인마다 `.sdd/<슬라이스>/feature-design.md`에 둔다.

## 섹션

아래 순서로 쓴다. 내용이 없는 섹션은 `없음`으로 쓴다.

| 섹션 | 쓰는 것 |
| --- | --- |
| 목표와 변경 범위 | 관련 요구사항 ID, 영향받는 슬라이스와 세그먼트 |
| 기능 흐름 | 정상 경로와 예외 경로 |
| 상태 전이와 비즈니스 규칙 | 표 `상태 \| 허용 동작 \| 전이 조건 \| 다음 상태`, 상태와 무관한 규칙 |
| 데이터와 인터페이스 | [API 명세서](api-spec.md), [데이터 모델](data-model.md), [화면 설계 문서](ux-design.md)의 해당 항목 링크 |
| 실패 처리 | 오류마다 사용자에게 보이는 결과, 재시도, 복구 |
| 검증 시나리오 | [검증 문서](verification.md)의 해당 요구사항 ID 링크 |

## 작성 기준

- 영향받는 슬라이스와 세그먼트는 [레이어](../architecture/layers.md)와 [세그먼트](../architecture/segments.md)의 이름으로 쓴다.
- 비즈니스 규칙은 경우를 빠짐없이 쓴다. 조건이 조합되면 조합마다 결과를 쓴다.
- 화면 배치와 움직임은 쓰지 않는다. 화면 설계 문서의 화면 ID로 가리킨다.
- 필드, 요청·응답 형식, 시나리오는 다시 쓰지 않는다. 해당 문서를 링크한다.
