# 접근성 규칙

## 키보드

- 키보드 포커스 표시는 원본에 없어도 유지한다. 없으면 키보드 사용자가 현재 위치를 알 수 없다.
- 포커스를 받은 요소는 화면에 전부 보여야 한다. 스크롤 영역에서 일부만 보이는 요소는 브라우저가 스크롤하지 않으므로, 포커스를 받을 때 `scrollIntoView({ block: "nearest", inline: "nearest" })`를 부른다.
- 조작으로 포커스된 요소가 사라지면 포커스를 옮길 위치를 설계안에 정한다. 정하지 않으면 포커스가 `body`로 떨어져 키보드 사용자가 처음부터 다시 이동해야 한다.

## 화면 낭독기

- 조작 결과로 바뀌는 상태는 화면 상태가 바뀌어도 남는 `role="status"` 요소 하나로 알린다. 첫 렌더링 때의 값은 알리지 않는다. 요소가 다시 만들어지면 값 변경이 알려지지 않을 수 있다.
- 즉시 주의가 필요한 오류는 `role="alert"`로 알린다. 오류를 보여 줄 때 나타나는 요소에 둔다.

## 명암비

- 쇼케이스 페이지(`/`)의 글자 명암비는 4.5:1 이상이다.
- 챌린지는 원본 색을 따르고 이 기준을 적용하지 않는다. 원본 재현이 챌린지의 목적이기 때문이다.
- 배경이 비치거나 그라디언트인 면에서는 글자가 놓이는 구간에서 잰다. 면의 평균 색으로 재면 밝은 구간의 글자를 놓친다.

## 사용자 설정

- 애니메이션 동작 줄이기 설정(`prefers-reduced-motion: reduce`)이 켜져 있으면 비필수 애니메이션을 줄이거나 끈다. 기능과 정보는 유지하고, 필요한 피드백은 움직임이 적은 표현으로 제공한다. 구현 방법은 [애니메이션 규칙](animation.md#애니메이션-동작-줄이기-설정-대응)을 따른다.
- 반투명 표현은 `prefers-reduced-transparency: reduce`이면 불투명 면으로 바꾼다.
