# 테마 규칙

디자인 토큰은 공통 토큰과 페이지 변수를 함께 이른다. 색, 글자, 여백과 간격, 모서리, 그림자와 효과, 가로세로 비율을 포함한다. 움직임 값은 [애니메이션 규칙](animation.md)을 따른다.

## 원칙

도메인 테마는 슬라이스 `theme.css`의 범위 클래스에서 공통 토큰의 값만 재정의해 구현한다. 그래야 shadcn 컴포넌트와 Tailwind 유틸리티를 도메인마다 그대로 쓸 수 있다. 공통 토큰은 전역 스타일(`src/app/styles/index.css`)이 정의한 토큰과, 유틸리티가 변수를 읽는 Tailwind 기본 theme 변수(`--text-*` 등)다.

도메인의 값은 전역 스타일에 쓰지 않는다. 그 공통 토큰을 재정의하지 않은 모든 도메인이 바뀐다. `/`도 다른 도메인과 같은 방식을 쓰고, 디자인 토큰으로 표현할 수 없는 스타일을 이루는 속성에만 CSS Module을 쓴다. 요소가 달라 한 컴포넌트로 묶을 수 없는 둘 이상의 컴포넌트가 이런 스타일을 함께 쓰면, 그 시각 요소(예: 카드 표면)에서 토큰으로 표현할 수 없는 속성과 그 속성과 함께 조건이나 상태에 따라 바뀌는 속성을 상태별 값까지 한 모듈로 모은다. 나머지 속성은 컴포넌트 유틸리티로 쓴다.

### theme.css 작성

- **파일** — `src/pages/<슬라이스>/ui/theme.css`. 가져오는 위치는 `eslint.config.js`가 판정한다.
- **범위 클래스** — `.theme-<슬라이스>`. 슬라이스 공통 최상위 요소에 한 번 붙인다.
- **페이지 변수** — `--<이름>`. 범위 클래스가 슬라이스를 구분하므로 슬라이스 접두사를 붙이지 않는다.

최상위 요소에 `bg-background text-foreground font-sans text-base min-h-dvh`를 붙인다. 범위 클래스의 재정의는 이 유틸리티들이 범위 안에서 다시 적용해야 상속된다.

`theme.css`에는 범위 클래스의 변수 재정의만 쓰고 `@theme`, `@apply` 같은 Tailwind 지시문은 쓰지 않는다. 요소의 스타일은 컴포넌트의 유틸리티가 맡고, 설계안에서 복사되는 파일이라 `index.css` 경로(`@reference`)에 의존할 수 없다.

기능 지원(`@supports`)이나 사용자 설정(`@media (prefers-*)`)에 따라 토큰 값만 바뀌면 `theme.css`에서 그 조건으로 감싼 범위 클래스의 변수 재정의로 쓴다. 색은 조건 안에서도 [다크 모드](#다크-모드)의 선택자를 따른다. 색 모드는 이 방식으로 바꾸지 않는다(`prefers-color-scheme` 제외). 모드는 `.dark` 선택자로만 바뀌고, 시스템 설정을 따르려면 `ui/`의 동작 컴포넌트가 `dark`를 붙인다. 두 경로가 섞이면 토글과 시스템 설정이 서로 덮어쓰기 때문이다. 화면 폭 경계(`md:` 같은 브레이크포인트)에서 값이 바뀌거나 배치·구조가 바뀌면 컴포넌트가 Tailwind 변형으로 쓴다. `clamp()`, `vw`처럼 경계 없이 폭에 따라 변하는 값은 폭 조건이 아니므로 다른 값처럼 [값 배치](#값-배치)에 따라 둔다.

페이지 변수는 두 층으로 둔다.

- **원본 값** — 원본 스타일 가이드가 이름 붙인 색은 쓰이지 않더라도 모두 그 이름으로 정의한다(`--neutral-900`). 원본 값은 공통 토큰과 역할 변수의 값으로만 쓰고, 컴포넌트에서 쓰지 않는다.
- **역할** — 공통 토큰에 없는 역할은 역할로 짓고, 색이 아닌 값은 종류를 끝에 붙인다(`--day-selector`, `--sky-gradient`, `--card-shadow`).

두 층 모두 공통 토큰과 같은 이름이나 Tailwind theme namespace(`--color-*`, `--font-*`, `--text-*`, `--spacing-*`, `--radius-*` 등)로 시작하는 이름을 쓰지 않는다. 같으면 공통 토큰의 재정의가 되고, namespace는 기본 유틸리티가 읽어 의도치 않은 재정의가 된다.

## 값 배치

도메인 기준에서 값을 정한 뒤(챌린지는 원본에서 뽑는다) 다음과 같이 둔다.

1. **같은 역할의 공통 토큰이 있으면** `theme.css`에서 그 토큰을 재정의한다. `--spacing`처럼 카테고리 절이 재정의를 막은 토큰은 예외다.
2. **없으면** 색이거나 반복되는 값만 `theme.css`에 페이지 변수로 새로 정의한다. 색은 한 번만 나와도 둔다. 다크 모드와 명암비 검사가 `theme.css`의 색을 기준으로 하기 때문이다.
3. **그 밖의 일회성 값**은 컴포넌트가 맡는다. Tailwind 기본 단위에 맞으면 기본 유틸리티(`gap-3`, `grid-cols-7`), 아니면 arbitrary value(`top-[117px]`)로 쓴다.

둘 이상의 도메인이 같은 역할의 페이지 변수를 두면 공통 토큰으로 올린다.

## 토큰 사용

컴포넌트는 `theme.css`에 둔 값을 그 형태에 맞는 방식으로 쓴다.

- **공통 토큰** — 유틸리티(`bg-primary`, `text-xl`)로 쓴다.
- **페이지 변수** — arbitrary value(`p-(--card-padding)`)로 쓴다. 종류가 붙은 페이지 변수를 `bg-`, `text-`, `border-`처럼 여러 속성을 맡는 유틸리티에 쓸 때는 타입 힌트를 붙인다(`bg-(image:--sky-gradient)`, `text-(length:--body-size)`). 빌드 시점에는 변수의 값을 볼 수 없어 색으로 처리하기 때문이다.
- **CSS Module** — `var(--이름)`으로 읽는다. `@reference`는 쓰지 않는다. 슬라이스의 모듈이 `app` 레이어의 전역 스타일을 참조하게 되기 때문이다. `@apply`도 `@reference` 없이 동작하지 않으므로 쓰지 않는다. 모듈 규칙은 Tailwind 레이어 밖이라 같은 속성의 유틸리티보다 우선하므로, 모듈이 맡은 속성은 컴포넌트에서 유틸리티로 다시 쓰지 않는다. 컴포넌트마다 달라야 하면 모듈에 변형 클래스를 둔다.

## 다크 모드

밝은 색은 `.theme-<슬라이스>`에, 어두운 색은 `.theme-<슬라이스>.dark`에 쓴다. 어두운 테마만 있는 도메인도 같다. `.theme-<슬라이스>`는 전역 `.dark`와 명시도가 같아 전역 값에 덮일 수 있기 때문이다. 원본 값과 색이 아닌 변수는 모드와 상관없이 `.theme-<슬라이스>`에 둔다. 그림자·그라디언트처럼 색이 섞인 값은 색 부분을 색 변수로 빼서 모드별 색 블록(`.theme-<슬라이스>`, `.theme-<슬라이스>.dark`)에 두고, 합성 변수는 `.theme-<슬라이스>`에 둔다. `transparent`처럼 모드와 상관없는 키워드는 합성 값 안에 그대로 쓴다.

- `dark`는 최상위 요소에 붙인다. 어두운 테마만 있으면 항상 붙이고, 토글이 있으면 `ui/`의 동작 컴포넌트가 붙였다 뗀다.
- 어두운 모드에서 쓰는 색 토큰은 모두 쓴다. 빠진 토큰은 전역 `.dark` 값이 된다.
- 슬라이스 컴포넌트에서 `dark:` 변형으로 색을 바꾸지 않는다. 색은 토큰 재정의로 바뀐다.

## 글자

### 글꼴

폰트는 `@fontsource` 패키지로 설치하고 슬라이스 `index.tsx`에서 가져온다.

본문은 `--sans-font`, 제목은 `--heading-font`를 재정의하고 `font-sans`, `font-heading`으로 쓴다. `--font-sans`, `--font-heading`은 유틸리티가 읽지 않으므로 재정의하지 않는다.

`--sans-font`를 바꾸면 `--heading-font`도 함께 쓴다. 전역 기본값은 범위 밖에서 계산되어, 빠뜨리면 제목이 전역 글꼴이 된다. 제목이 본문과 같으면 `var(--sans-font)`로 쓴다.

### 글자 크기

원본의 글자 단계는 크기 순서를 지키며 가장 가까운 Tailwind 단계에 대응시켜 `--text-<단계>`를 재정의한다. 본문 크기는 `--text-base`다. 원본이 행간을 정의했으면 `--text-<단계>--line-height`도 재정의한다.

## 간격

`--spacing`은 재정의하지 않는다. 숫자 간격 유틸리티가 모두 이 값의 배수라서 shadcn 컴포넌트 크기까지 바뀐다.

## 모서리

원본의 기본 반경을 `--radius`(`rounded-lg`)에 둔다. 다른 `rounded-*` 단계는 그 배수로 따라오고, 배수로 맞지 않는 반경은 [값 배치](#값-배치)에 따른다.

## Portal

`body`로 렌더링되는 부품(메뉴, 팝오버, 다이얼로그)은 범위 밖이다. 콘텐츠 요소의 `className`에 범위 클래스와 `font-sans text-base`를 넘기고, 최상위 요소에 `dark`가 있으면 `dark`도 넘긴다.
