# FM Showcase

Frontend Mentor 챌린지 구현 결과물을 모아 보여주는 프론트엔드 쇼케이스.

## 목표

OMC(oh-my-claudecode)를 만들지 않고 가져다 쓰되, 그 위에 결정론적 구조를 얹어 AI의 비결정성을 통제하고, 통제가 작동한 기록을 증거로 남긴다.

- 증명하는 것은 AI 도구를 만드는 능력이 아니라, 외부 도구를 가져와 의도대로 통제하는 능력이다.
- 쇼케이스 사이트는 그 통제 아래 만든 **수단이자 결과물**이다.

## 접근 방식

OMC는 외부 도구이며, 이 프로젝트의 작업물은 그 위에 얹는 결정론적 구조다. 첫 적용 사례는 TDD다. OMC의 `tdd`는 프롬프트 수준이라 비결정적이므로, 테스트 작성을 LLM 바깥의 코드로 강제한다.

### 강제와 안내

규칙은 기계가 판정할 수 있는지로 나눈다.

| 등급 | 기준 | 방식 |
| ---- | ---- | ---- |
| 강제 | 기계가 참/거짓을 판정할 수 있는 규칙 | CI가 판정하고, 실패하면 merge를 차단한다 |
| 안내 | 판정에 의미 판단이 필요한 규칙 | `AGENTS.md`로 주입한다. 에이전트가 따르기를 기대하는 비결정 규칙이다 |

- 기계로 판정되게 만들 수 있는 규칙은 안내에 두지 않고 강제로 올린다. 안내는 아직 강제로 만들지 못한 규칙이다.
- 강제는 규칙의 충족 여부만 보장하며, 테스트의 품질처럼 의미 판단이 필요한 영역은 보장하지 않는다.

### 파이프라인

```
로컬 개발 (에이전트 작업) → 기록 생성 → push, PR → CI 독립 실행
                                                      ├ 통과 → merge 가능
                                                      └ 실패 → merge 차단 → 실패 로그를 로컬로 가져옴
                                                                          → 로컬에서 수정, 기록 생성
                                                                          → 같은 PR에 push → CI 재실행
```

- 기록은 LLM이 아니라 결정론적 코드가 실제 실행 결과를 그대로 적는다.
- CI가 최종 권위다. 로컬 훅은 조기 피드백용이다.
- 같은 PR에서 3회 연속 실패하면 루프를 멈추고 사람에게 넘긴다. 멈춘 사실도 기록한다.

### 증거

- 증거는 브라우저 UI가 아니라 저장소 문서로 남긴다.
- 연출한 사례가 아니라 정상 작업 중 쌓인 실행 기록이다. 실패 → 수정 → 통과 흐름이 그대로 남는다.
- 한계: 차단이 한 번도 없었던 챌린지는 통과 기록만 남는다.

## 도메인

Frontend Mentor 챌린지 구현물의 목록·상세 쇼케이스.

- 챌린지 카드 목록과 필터(난이도, 사용 기술 등)
- 챌린지 상세: 설명, 구현 스택, 라이브 링크, 저장소 링크, 검증 기록 문서 링크

사이트는 증거를 보여주는 뷰어가 아니라 증거 문서로 가는 진입점이다.

## 기술 스택

| 영역 | 선택 |
| ---- | ---- |
| 빌드 | Vite |
| UI | React, TypeScript |
| 테스트 | Vitest, Testing Library |
| AI 개발 도구 | OMC (외부 도구, `ralplan`, `tdd`, `verify`) |

## 아키텍처 방향

<!-- - **명세 우선**: `docs/`의 명세가 테스트와 구현의 기준이다. -->
- **순수 로직과 UI 분리**: 필터·정렬 등 규칙은 순수 함수로 두고 단위 테스트로 검증한다. 컴포넌트는 표시와 상호작용만 맡는다.
- **데이터는 정적 데이터로 시작**: 챌린지 목록은 타입이 있는 정적 데이터로 두고, 필요가 생길 때 확장한다.
- **증거는 저장소에 남긴다**: Red/Green 실행 기록을 저장소에 커밋한다.
