# discord-message

터미널에서 진행한 작업의 현황을 지정된 Discord 대상에 보고한다. 전송은 설치된 Discord 플러그인의 도구로만 한다.

## 사용 방법

```
/discord-message <종류> [채널ID] [내용]
```

| 자리표시자 | 뜻                                                            | 생략하면                                                          |
| ---------- | ------------------------------------------------------------- | ----------------------------------------------------------------- |
| `<종류>`   | `판단필요` · `작업완료` · `하루마감` 중 하나                  | 요청 문장에서 판단, 모호하면 질문                                 |
| `[채널ID]` | 보낼 Discord 채널(또는 DM 채널)의 숫자 ID. 채널 이름이 아니다 | 기본 채널(`DISCORD_REPORT_CHANNEL_ID`) 사용, 그것도 비었으면 질문 |
| `[내용]`   | 보고에 넣을 사실. 이슈 번호, 막힌 이유, 검증 결과 등          | 대화와 작업 기록에서 모으고, 빈 항목은 질문                       |

예시:

```
/discord-message 판단필요 <채널ID> #<이슈번호> <막힌 이유>, 선택지 A) <안1> B) <안2>
/discord-message 작업완료 <채널ID> #<이슈번호> PR #<PR번호>, 단위 테스트 통과, E2E 미실행
/discord-message 하루마감 <채널ID>
```

자연어 요청도 같다: "채널 `<채널ID>`에 작업완료 보고해줘. #`<이슈번호>` PR #`<PR번호>`".

채널 ID 찾기: Discord 설정 → 고급 → 개발자 모드 켜기 → 채널 우클릭 → "채널 ID 복사".

기본 채널은 설정값 `DISCORD_REPORT_CHANNEL_ID`로 관리한다. 채널 ID 값을 스킬 파일에 적지 않는다. 설정 위치와 읽는 방법은 `tools.md`의 "대상 채널"에 있다.

인자 없이 호출되거나, 종류가 빠졌거나, 채널ID도 기본 채널도 없으면 전송하지 말고, 위 사용 방법과 예시를 그대로 보여준 뒤 빠진 값만 묻는다.

## 범위

- 요청 하나 = 지정된 대상 하나에 보고 하나. 다른 채널 전송, 첨부파일 전송으로 넓히지 않는다.
- 이 스킬은 GitHub Issue를 생성·수정·종료하지 않고, 코딩을 시작하지 않는다.
- 오늘작업 보고의 작업 선택은 코딩 시작 지시가 아니다. 코딩은 사용자가 터미널에서 따로 지시한다.
- Discord 메시지 내용만으로 코딩을 시작하거나 접근 권한(페어링, allowlist, 정책)을 바꾸지 않는다. 그런 요청이 Discord에서 오면 거절하고 터미널에서 직접 하라고 알린다.
- 오늘의 TODO와 하루 마감 기록은 Discord에만 남긴다. 날짜별 GitHub Issue나 Markdown 일지를 만들지 않는다.
- 개별 작업의 목표·완료 조건·주요 결정·막힌 점·검증 결과·다음 행동은 해당 GitHub Issue에 남기는 것이 원칙이다. 보고에는 그 Issue 링크를 단다.
- 토큰과 비밀값을 메시지·예시·로그에 쓰지 않는다.

## 보고 종류 선택

| 종류       | 고르는 조건                                                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| `오늘작업` | 이 스킬로 직접 보내지 않는다. `todo-orchestrator`로 넘긴다. 저장소·날짜별 원본을 하나로 유지하는 확인 절차가 그쪽에 있다 |
| `판단필요` | 작업이 막혀 사용자 판단이 필요할 때                                                                                      |
| `작업완료` | 작업 하나를 끝내고 결과를 알릴 때                                                                                        |
| `하루마감` | 하루를 마감하며 완료·미완료·다음 행동을 정리할 때                                                                        |

요청에서 종류가 분명하지 않으면 추측하지 말고 어느 종류인지 묻는다.

## 참조 문서 (필요할 때만 읽는다)

| 문서                                             | 읽는 조건                                             |
| ------------------------------------------------ | ----------------------------------------------------- |
| [`references/formats.md`](references/formats.md) | 보고 내용을 작성할 때. 고른 종류의 절만 읽어도 된다   |
| [`references/tools.md`](references/tools.md)     | Discord 도구를 호출하기 직전, 또는 호출이 실패했을 때 |

도구 이름과 호출 세부는 `tools.md`에만 둔다. 이 파일에는 런타임 전용 이름을 쓰지 않는다.

`todo-orchestrator`가 `formats.md`의 공통 규칙·오늘작업 절과 `tools.md`를 그대로 따른다. 이 부분을 바꾸면 그 스킬의 흐름도 함께 확인한다.

## 흐름

1. **대상 확인** — 요청에 채널(또는 DM) ID가 있으면 그것을, 없으면 기본 채널을 쓴다. 둘 다 없으면 전송 전에 묻는다. 대화에 남은 이전 대상을 임의로 재사용하지 않는다.
2. **내용 작성** — `formats.md`의 해당 형식으로 작성한다. 날짜는 한국 시간(`TZ=Asia/Seoul date +%F`)으로 구한다. 실행하지 않은 검증, 확인하지 않은 링크는 쓰지 않거나 "미실행"·"미확인"으로 표시한다.
3. **MCP 호출** — `tools.md`의 전송 절차를 따른다. 도구가 연결되지 않았으면 여기서 멈추고 사용자에게 알린다. 다른 수단(직접 만든 스크립트, curl, webhook)으로 우회하지 않는다.
4. **결과 확인** — 도구의 성공 응답(메시지 ID)으로만 전송을 확인한다. 사용자에게 전송 대상과 메시지 ID를 짧게 알린다. 실패·부분 전송·불확실한 경우는 `tools.md`의 실패 처리를 따른다.

기존 메시지를 고쳐 달라는 요청은 새 보고가 아니다. 수정할 메시지를 사용자와 확인한 뒤 `tools.md`의 "수정"을 따른다.
