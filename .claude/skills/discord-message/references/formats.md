# 보고 형식

보고 내용을 쓸 때 읽는다. 공통 규칙을 먼저 보고, 고른 종류의 절만 읽으면 된다.

예시의 작업명·번호는 형식 설명용 가상 값이다. 실제 하루 기록은 이 파일에 저장하지 않는다.

---

## 공통 규칙

### 제목 줄

모든 보고의 첫 줄은 아래 모양으로 고정한다. 하루마감이 이 줄로 그날 오늘작업 보고를 찾으므로 바꾸지 않는다.

```
## <이모지> <종류> · YYYY-MM-DD KST
```

| 종류                            | 이모지 | 제목 줄 예                                      |
| ------------------------------- | ------ | ----------------------------------------------- |
| 오늘작업                        | 📋     | `## 📋 오늘작업 · 2026-01-15 KST`               |
| 판단필요                        | ⛔     | `## ⛔ 판단필요 · 2026-01-15 KST`               |
| 작업완료                        | ✅     | `## ✅ 작업완료 · 2026-01-15 KST`               |
| 작업완료, 완료 조건 일부 미충족 | ⚠️     | `## ⚠️ 작업완료 (일부 미충족) · 2026-01-15 KST` |
| 하루마감                        | 🌙     | `## 🌙 하루마감 · 2026-01-15 KST`               |

날짜는 한국 시간 기준이다.

### 본문 모양

- 섹션 제목은 `**굵게**`로 쓰고, 섹션 사이에는 빈 줄을 하나 둔다.
- 항목은 `-` 목록으로 쓴다. 한 항목은 한 줄로 끝낸다.
- 링크는 `<https://...>`처럼 꺾쇠로 감싼다. 미리보기 카드가 붙지 않아 메시지가 짧게 유지된다.
- 표는 쓰지 않는다. Discord에서 렌더링되지 않는다.
- 한 메시지는 2000자 이하로 쓴다. 넘으면 요약해서 줄인다.

### 사실만 쓰기

- 검증 항목마다 `통과` · `실패` · `미실행` 중 하나를 붙인다. 실행하지 않은 검증을 통과로 쓰지 않는다. `미실행`에는 `미실행 (환경 없음)`처럼 괄호로 사유를 붙인다.
- 미완료 작업을 완료로 쓰지 않는다. 일부만 끝났으면 끝난 부분과 남은 부분을 나눠 쓴다.
- 이슈·PR 링크는 존재를 확인한 것만 쓴다.

### 관련 이슈 표기

| 상황               | 표기               |
| ------------------ | ------------------ |
| 이슈가 있고 확인함 | `#번호 <링크>`     |
| 이슈가 없음        | `관련 이슈 없음`   |
| 있는지 확인 못 함  | `관련 이슈 미확인` |

이 스킬은 이슈를 만들지 않는다. 이슈가 없다고 이슈 생성을 제안하지도 않는다.

### 비밀값

토큰, 키, webhook URL은 쓰지 않는다.

---

## 오늘작업

오늘 사용자가 고른 작업과 관련 이슈. 작업은 사용자가 고른다. 에이전트가 더하거나 빼지 않는다.

```
## 📋 오늘작업 · 2026-01-15 KST

**오늘 할 작업**
- #101 로그인 폼 유효성 검사 <https://github.com/<owner>/<repo>/issues/101>
- #102 목록 페이지 로딩 상태 표시 <https://github.com/<owner>/<repo>/issues/102>
```

---

## 판단필요

막힌 이유, 필요한 판단, 다음 행동. 판단은 사용자가 고를 수 있는 선택지로 쓴다.

```
## ⛔ 판단필요 · 2026-01-15 KST
#101 로그인 폼 유효성 검사 <https://github.com/<owner>/<repo>/issues/101>

**막힌 이유**
- 이메일 형식 규칙이 이슈 완료 조건에 없음

**필요한 판단**
- A) RFC 수준으로 검사
- B) `@` 포함 여부만 검사

**다음 행동**
- 판단을 받으면 이슈에 결정을 기록하고 구현을 이어감
```

---

## 작업완료

변경 요약, 완료 조건 충족 여부, 검증 결과, 관련 링크.

- 검증이 진행 중이면 보내지 않는다. 검증을 실제로 실행한 뒤에 보낸다.
- 관련 이슈가 없으면 제목 아래 줄을 `<작업명> — 관련 이슈 없음`으로 쓴다.
- `**링크**` 섹션은 남길 링크(이슈·PR)가 있을 때만 둔다.
- 완료 조건은 이슈에 적힌 항목을 그대로 옮겨 하나씩 표시한다.
- 관련 이슈가 없으면 사용자가 대화에서 정한 조건을 쓰고, 섹션 제목을 `**완료 조건** (이슈 없음, 대화 기준)`으로 쓴다. 정한 조건이 없으면 사용자에게 묻는다.
- 하나라도 미충족이면 제목 줄을 `⚠️ 작업완료 (일부 미충족)`으로 쓴다.

```
## ⚠️ 작업완료 (일부 미충족) · 2026-01-15 KST
#102 목록 페이지 로딩 상태 표시

**변경 요약**
- 목록 조회 중 스켈레톤 표시
- 실패 시 재시도 버튼 추가

**완료 조건**
- ✅ 로딩 중 스켈레톤 표시
- ❌ 실패 시 재시도 — 버튼만 있고 동작은 미구현

**검증**
- 단위 테스트: 통과
- E2E: 미실행 (환경 없음)

**링크**
- 이슈 <https://github.com/<owner>/<repo>/issues/102>
- PR <https://github.com/<owner>/<repo>/pull/103>
```

---

## 하루마감

오늘 완료한 일, 미완료 작업, 다음 행동. 그날 오늘작업 보고와 비교해 빠진 작업이 없게 쓴다. 그날 오늘작업 보고를 찾는 방법은 `tools.md`의 "기록 조회"를 따른다.

오늘작업 목록에 없던 작업도 완료·미완료에 넣고, 항목 끝에 `(목록 외)`를 붙인다.

```
## 🌙 하루마감 · 2026-01-15 KST

**완료**
- #102 목록 페이지 로딩 상태 표시 (재시도 동작 제외)

**미완료**
- #101 로그인 폼 유효성 검사 — 이메일 규칙 판단 대기

**다음 행동**
- #101 판단을 받은 뒤 구현
- #102 재시도 동작 구현
```

그날 오늘작업 보고를 찾지 못했으면 비교 결과를 지어내지 않는다. 첫 줄 아래에 `오늘작업 기록 없음 — 대화 기준으로 작성`이라고 쓴다.
