# 보고 형식

보고 내용을 쓸 때 읽는다. 공통 규칙을 먼저 보고, 고른 종류의 절만 읽으면 된다.

예시의 작업명·번호는 형식 설명용 가상 값이다. 실제 하루 기록은 이 파일에 저장하지 않는다.

---

## 공통 규칙

### 제목 줄

모든 보고의 첫 줄은 아래 모양으로 고정한다. 여러 저장소가 같은 채널에 보고하므로, 그날 오늘작업 원본은 이 줄의 저장소와 날짜로 찾는다(`tools.md`의 "기록 조회"). 그래서 이 모양을 바꾸지 않는다.

```
## <이모지> <종류> · <repo> · YYYY-MM-DD KST
```

| 종류                            | 이모지 | 제목 줄 예                                               |
| ------------------------------- | ------ | -------------------------------------------------------- |
| 오늘작업                        | 📋     | `## 📋 오늘작업 · <repo> · 2026-01-15 KST`               |
| 판단필요                        | ⛔     | `## ⛔ 판단필요 · <repo> · 2026-01-15 KST`               |
| 작업완료                        | ✅     | `## ✅ 작업완료 · <repo> · 2026-01-15 KST`               |
| 작업완료, 완료 조건 일부 미충족 | ⚠️     | `## ⚠️ 작업완료 (일부 미충족) · <repo> · 2026-01-15 KST` |
| 하루마감                        | 🌙     | `## 🌙 하루마감 · <repo> · 2026-01-15 KST`               |

날짜는 한국 시간 기준이다. `<repo>`는 보고 대상 저장소의 이름이다(owner 제외, 예: `fm-showcase`). 저장소들이 모두 같은 계정이라 owner는 구분에 보탬이 없고 제목만 길어진다.

### 본문 모양

- 제목 줄과 본문, 섹션 사이, 섹션 제목과 목록 사이에는 빈 줄을 하나 둔다. 섹션 제목은 `**굵게**`로 쓴다.
- 항목은 `-` 목록으로 쓰고 작업명은 `**굵게**`로 강조한다. 이슈 번호와 링크는 강조하지 않는다.
- 항목은 한 줄로 쓰되, 선행 조건과 다음 행동은 바로 다음 줄에 두 칸 들여 쓴다. 선행이 상위 묶음이면 남은 하위 작업을 한 줄 더 쓰고 두 칸 더 들여 쓴다. 다음 행동은 `→ 다음: <다음 행동>`으로 쓴다.
- 이모지는 제목, 완료 조건의 충족 여부, 오늘작업의 상태·관계 안내에만 쓴다. 장식용 구분선이나 인용 블록은 쓰지 않는다.
- 이슈·PR 링크는 `[#번호](<https://...>)`처럼 번호에 건다. 긴 URL을 본문에 따로 표시하지 않고, URL은 꺾쇠로 감싸 미리보기 카드를 억제한다. 상태·관계 안내에서 번호를 다시 언급할 때는 일반 텍스트로 쓴다.
- 표는 쓰지 않는다. Discord에서 렌더링되지 않는다.
- 한 메시지는 2000자 이하로 쓴다. 넘으면 요약해서 줄인다.

### 사실만 쓰기

- 검증 항목은 `<검증명> · **통과|실패|미실행**`으로 쓴다. 상태는 셋 중 하나만 쓰고, 실행하지 않은 검증을 통과로 쓰지 않는다. `미실행`에는 `E2E · **미실행** — 실행 환경 없음`처럼 사유를 붙인다.
- 미완료 작업을 완료로 쓰지 않는다. 일부만 끝났으면 끝난 부분과 남은 부분을 나눠 쓴다.
- 이슈·PR 링크는 존재를 확인한 것만 쓴다.

### 관련 이슈 표기

| 상황               | 표기                           |
| ------------------ | ------------------------------ |
| 이슈가 있고 확인함 | `[#번호](<이슈 URL>) **제목**` |
| 이슈가 없음        | `관련 이슈 없음`               |
| 있는지 확인 못 함  | `관련 이슈 미확인`             |

이 스킬은 이슈를 만들지 않는다. 이슈가 없다고 이슈 생성을 제안하지도 않는다.

### 비밀값

토큰, 키, webhook URL은 쓰지 않는다.

## 오늘작업

오늘 사용자가 고른 작업과 관련 이슈. 작업은 사용자가 고른다. 에이전트가 더하거나 빼지 않는다.

- 섹션은 카테고리(`bug`, `feature`, `refactor`, `other`)이고, 항목이 없는 섹션은 쓰지 않는다. 카테고리와 순서는 `todo-orchestrator`의 `references/classification.md`를 따른다.
- 열린 선행이 있는 항목 바로 아래에 두 칸 들여 `← #번호`를 한 줄로 쓴다. 상위 묶음이 선행이면 `← #19` 다음 줄에 두 칸 더 들여 `└─ #29, #30 남음`을 써서 두 줄로 표시한다. 선행 판정과 상세 표기법은 `classification.md`의 "실제 선행"과 "메시지 관계 표기법"을 따른다. 상태 표시는 관계 줄과 구분한다.

```
## 📋 오늘작업 · <repo> · 2026-01-15 KST

**feature**

- [#101](<https://github.com/<owner>/<repo>/issues/101>) **로그인 폼 유효성 검사**
- [#102](<https://github.com/<owner>/<repo>/issues/102>) **목록 페이지 로딩 상태 표시**
  ← #101
- [#104](<https://github.com/<owner>/<repo>/issues/104>) **인증 오류 메시지 연결**
  ← #101
- [#105](<https://github.com/<owner>/<repo>/issues/105>) **인증 오류 처리**
  ← #100
    └─ #101, #104 남음

**other**

- [#103](<https://github.com/<owner>/<repo>/issues/103>) **CI 캐시 설정**
```

## 판단필요

막힌 이유와 사용자가 고를 선택지. 제목 줄이 이미 "판단필요"이므로 선택지 섹션 이름은 `**선택지**`로 쓴다.

- 판단을 받은 뒤의 기본 행동(이슈에 결정을 기록하고 이어감)은 쓰지 않는다. 기본과 다른 행동이 있을 때만 `**다음 행동**`을 둔다.
- 선택지의 라벨은 `**A)**`, `**B)**`처럼 굵게 쓴다.

```
## ⛔ 판단필요 · <repo> · 2026-01-15 KST

[#101](<https://github.com/<owner>/<repo>/issues/101>) **로그인 폼 유효성 검사**

**막힌 이유**

- 이메일 형식 규칙이 이슈 완료 조건에 없음

**선택지**

- **A)** RFC 수준으로 검사
- **B)** `@` 포함 여부만 검사
```

## 작업완료

완료 조건 충족 여부, 검증 결과, PR 링크.

- 검증이 진행 중이면 보내지 않는다. 검증을 실제로 실행한 뒤에 보낸다.
- 제목 아래에는 빈 줄 뒤에 `[#번호](<이슈 URL>) **제목**`을 쓴다. 관련 이슈가 없으면 `**<작업명>** — 관련 이슈 없음`으로 쓴다.
- 완료 조건은 이슈에 적힌 항목을 그대로 옮겨 하나씩 표시한다.
- 관련 이슈가 없으면 사용자가 대화에서 정한 조건을 쓰고, 섹션 제목을 `**완료 조건** (이슈 없음, 대화 기준)`으로 쓴다. 정한 조건이 없으면 사용자에게 묻는다.
- 하나라도 미충족이면 제목 줄을 `⚠️ 작업완료 (일부 미충족)`으로 쓴다.
- `**변경 요약**`은 완료 조건에 드러나지 않는 변경이 있을 때만 둔다. 완료 조건과 같은 내용을 반복하지 않는다.
- `**PR** [#번호](<PR URL>)` 줄은 PR이 있을 때만 둔다. 이슈 링크는 제목 아래 줄에 있으므로 다시 쓰지 않는다.

```
## ⚠️ 작업완료 (일부 미충족) · <repo> · 2026-01-15 KST

[#102](<https://github.com/<owner>/<repo>/issues/102>) **목록 페이지 로딩 상태 표시**

**완료 조건**

- ✅ 로딩 중 스켈레톤 표시
- ❌ 실패 시 재시도 — 버튼만 있고 동작은 미구현

**검증**

- 단위 테스트 · **통과**
- E2E · **미실행** — 실행 환경 없음

**PR** [#103](<https://github.com/<owner>/<repo>/pull/103>)
```

## 하루마감

오늘 완료한 일과 미완료 작업. 그날 오늘작업 보고와 비교해 빠진 작업이 없게 쓴다. 그날 오늘작업 보고를 찾는 방법은 `tools.md`의 "기록 조회"를 따른다.

- 오늘작업 목록에 없던 작업도 완료·미완료에 넣고, 항목 끝에 `(목록 외)`를 붙인다.
- 일부만 끝난 작업은 미완료에 두고 끝난 부분과 남은 부분을 함께 쓴다.
- 미완료 항목 바로 다음 줄에 두 칸 들여 `→ 다음: <다음 행동>`을 붙인다. 다음 행동을 별도 섹션으로 다시 나열하지 않는다.
- 해당 항목이 없는 섹션은 `- 없음`으로 쓴다.

```
## 🌙 하루마감 · <repo> · 2026-01-15 KST

**완료**

- [#100](<https://github.com/<owner>/<repo>/issues/100>) **목록 API 연결**

**미완료**

- [#101](<https://github.com/<owner>/<repo>/issues/101>) **로그인 폼 유효성 검사** — 이메일 규칙 판단 대기
  → 다음: 판단 후 구현
- [#102](<https://github.com/<owner>/<repo>/issues/102>) **목록 페이지 로딩 상태 표시** — 스켈레톤 완료, 재시도 미구현
  → 다음: 재시도 구현
```

그날 오늘작업 보고를 찾지 못했으면 비교 결과를 지어내지 않는다. 첫 줄 아래에 `오늘작업 기록 없음 — 대화 기준으로 작성`이라고 쓴다.
