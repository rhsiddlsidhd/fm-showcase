# executor 입출력

- 역할: `수정 가능 경로`만으로 테스트를 통과시킨다
- 문서 인덱스: `docs/architecture/README.md`
- 판정 값: `DONE`, `TEST_ISSUE`, `PLAN_ISSUE`

## 입력 파일 내용

| 섹션            | 채우는 내용                                                           | 가져오는 곳                                                      |
| --------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 요구사항        | 모든 요구사항의 ID와 문구                                             | spec.md `## 요구사항`의 첫 두 칸                                 |
| 수정 가능 경로  | `impl` 행 경로                                                        | spec.md `## 파일 배치`                                           |
| 참조 파일       | `test` 행 경로. 용도는 "통과시킬 테스트"                              | spec.md `## 파일 배치`                                           |
| 인터페이스 계약 | 모든 행                                                               | spec.md `## 인터페이스 계약`                                     |
| 테스트 대응     | 요구사항 / 테스트 파일 / 테스트 이름 (`실패 이유` 칸은 빼고)          | 가장 최근 test-engineer 보고서 `## 테스트 대응`                  |
| 재호출 사유     | `검사 항목`의 `FAIL` 행, 또는 위반 경로, 또는 배치 제안을 거절한 이유 | 직전 verifier 보고서, `{NN}_violations.txt`, 오케스트레이터 판단 |

배치 표의 `이유` 칸, test-engineer 보고서의 `실패 이유`·`근거` 섹션은 옮기지 않는다.

## 작업 지시

- 테스트가 통과하도록 구현한다. `checks.sh executor`가 통과해야 한다.
- 테스트가 틀렸거나 요구사항과 맞지 않으면 테스트를 고치지 말고 `TEST_ISSUE`로 끝낸다. 요구사항 문구와 테스트 코드를 비교해 판단한다.
- `인터페이스 계약`대로 내보낸다. 계약을 바꿔야 한다고 판단하면 바꾸지 말고 `PLAN_ISSUE`로 끝낸다.
- `수정 가능 경로`에 없는 파일이 필요하면 만들지 말고 `PLAN_ISSUE`로 끝낸다.

## 에이전트별 출력 섹션

```markdown
## 요구사항 구현

| 요구사항 | 구현 파일 | 통과한 테스트 |
| -------- | --------- | ------------- |
| R1       | `{path}`  | `R1: {name}`  |

## 테스트 문제

| 테스트 위치     | 문제            | 요구사항 근거 |
| --------------- | --------------- | ------------- |
| `{path}:{line}` | {무엇이 틀렸나} | R{n} 문구     |

## 배치 제안

| 경로     | 역할 | 레이어/세그먼트 | 이유                     |
| -------- | ---- | --------------- | ------------------------ |
| `{path}` | impl | {layer/segment} | {왜 기존 경로로 안 되나} |
```

- `DONE`이면 `테스트 문제`, `배치 제안`은 `없음`이다.
- `TEST_ISSUE`면 `테스트 문제`가, `PLAN_ISSUE`면 `배치 제안`이 비어 있으면 안 된다.
