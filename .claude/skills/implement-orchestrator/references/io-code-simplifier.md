# code-simplifier 입출력

- 역할: `수정 가능 경로`의 파일을 동작을 바꾸지 않고 정리한다
- 문서 인덱스: `docs/architecture/README.md`
- 판정 값: `DONE`, `PLAN_ISSUE`

## 입력 파일 내용

| 섹션           | 채우는 내용                                      | 가져오는 곳                                |
| -------------- | ------------------------------------------------ | ------------------------------------------ |
| 요구사항       | `없음`                                           | —                                          |
| 수정 가능 경로 | `impl` 행 경로                                   | spec.md `## 파일 배치`                     |
| 참조 파일      | `test` 행 경로. 용도는 "동작 보존 확인용 테스트" | spec.md `## 파일 배치`                     |
| 테스트 대응    | `없음`                                           | —                                          |
| 재호출 사유    | 위반 경로, 또는 배치 제안을 거절한 이유          | `{NN}_violations.txt`, 오케스트레이터 판단 |

요구사항은 넘기지 않는다. 동작을 보존하는지는 테스트로 판단한다.

## 작업 지시

- `수정 가능 경로`의 파일만 정리한다. 테스트가 확인하는 동작은 바꾸지 않는다.
- 새 파일로 분리하는 편이 낫다고 판단하면 분리하지 말고 `PLAN_ISSUE`로 제안한다.
- 정리한 뒤 `checks.sh code-simplifier`가 통과해야 한다.

## 에이전트별 출력 섹션

```markdown
## 정리 내역

| 파일     | 바꾼 것 | 동작 보존 근거                      |
| -------- | ------- | ----------------------------------- |
| `{path}` | {한 줄} | {통과한 테스트 / 순수 이름 변경 등} |

## 배치 제안

| 경로 | 역할 | 레이어/세그먼트 | 이유 |
| ---- | ---- | --------------- | ---- |
```

- 바꿀 것이 없으면 `정리 내역`에 `없음`을 쓰고 `DONE`으로 끝낸다.
