# 공통 입출력 형식

모든 에이전트 호출에 쓴다. 오케스트레이터는 호출마다 전용 입력 파일을 쓰고, 아래 프롬프트 블록에 에이전트별 내용(`io-{agent}.md`)을 채워 호출한다. 출력 형식은 파일 경로로 넘기지 않고 프롬프트에 그대로 복사한다. 에이전트가 형식 파일을 읽지 않아도 지킬 수 있게 하기 위해서다.

## 입력 최소화

에이전트의 입력은 그 에이전트의 작업에 필요한 것만 담는다. 다른 에이전트가 무엇을 근거로 판단했는지(문서 링크, 판단 이유)는 넘기지 않는다.

- 이유: 필요 없는 문서는 컨텍스트만 늘리고 작업 초점을 흐린다. 예를 들어 executor의 일은 테스트 코드를 통과시키는 것이다. 테스트를 어떻게 설계했는지는 이미 테스트 코드에 담겨 있다.
- 그래서 verifier를 뺀 에이전트는 `spec.md`와 다른 에이전트의 보고서를 직접 읽지 않는다. 오케스트레이터가 필요한 항목만 옮긴 전용 입력 파일 하나를 받는다.
- 전용 입력 파일과 프롬프트에는 그 에이전트의 문서 인덱스 말고는 `docs/` 경로를 쓰지 않는다. 다른 파일에서 항목을 옮길 때도 문서 링크는 빼고 `파일:줄`과 문제 문장만 옮긴다.
- verifier는 예외다. 모든 판단을 독립적으로 검증해야 하므로 원본 파일을 모두 받는다(`io-verifier.md`).

## 검사 명령

검사는 `bash .claude/skills/implement-orchestrator/scripts/checks.sh <agent>` 하나로 실행한다. 에이전트는 개별 `npm run` 명령을 고르지 않는다.

- 명령 목록의 원본은 `.github/workflows/ci.yml`의 `npm run` 단계다. 스크립트가 그 파일에서 기계적으로 추출하므로, 하네스는 목록을 갖지 않고 에이전트별 제외 규칙만 갖는다. 에이전트는 `ci.yml`을 읽지 않는다.
- 이유: 하네스가 CI보다 적게 검사하면 PASS로 끝난 결과가 PR에서 실패한다. 목록을 하네스에 복사하면 CI가 바뀔 때 하네스만 옛 목록으로 남는다.
- 명령을 직렬로 모두 실행하고, 실패해도 멈추지 않는다. 한 번 실행으로 고칠 것을 전부 보여 주기 위해서다. 병렬로 돌리면 출력이 섞이고 자원 경쟁으로 불안정한 실패가 생긴다.
- 출력의 `## 검사 결과` 표를 보고서 `## 실행한 명령`에 그대로 옮긴다. 실패한 명령의 오류 출력은 `### 실패:` 섹션에 있다.
- `test:e2e`는 `--e2e`를 줄 때만 실행한다. 오케스트레이터는 e2e 테스트나 그 대상이 바뀌었을 때 프롬프트에 이 옵션을 적는다.

## 전용 입력 파일

`_workspace/{NN}_{agent}_input.md`. 오케스트레이터만 쓴다. 섹션 순서와 제목을 고정하고, 해당 내용이 없으면 `없음`이라고 쓴다. 섹션마다 채우는 내용은 `io-{agent}.md`의 「입력 파일 내용」 표를 따른다. `참조 파일`의 용도 칸에는 무엇에 쓰는지만 쓰고, 계약이나 판단(예: 어떤 종류의 컴포넌트인지)을 쓰지 않는다. 계약은 `인터페이스 계약` 섹션에만 둔다.

```markdown
# {agent} 입력 (호출 {NN})

## 요구사항

| ID  | 요구사항                       |
| --- | ------------------------------ |
| R1  | {spec.md 요구사항 문구 그대로} |

## 수정 가능 경로

- `{path}`

## 참조 파일

| 경로     | 용도                               |
| -------- | ---------------------------------- |
| `{path}` | {읽기만 한다. 무엇에 쓰는지 한 줄} |

## 인터페이스 계약

| 경로     | 내보내는 이름 | 형태     |
| -------- | ------------- | -------- |
| `{path}` | `{Name}`      | `{형태}` |

## 테스트 대응

| 요구사항 | 테스트 파일 | 테스트 이름 |
| -------- | ----------- | ----------- |

## 재호출 사유

| 위치                      | 문제              | 출처                                            |
| ------------------------- | ----------------- | ----------------------------------------------- |
| `{path}:{line}` 또는 경로 | {고칠 것 한 문장} | 호출 {NN} {판정} / 소유권 위반 / 배치 제안 거절 |
```

## 프롬프트

```markdown
# 작업: {에이전트 역할 한 줄}

## 저장소 규칙

- 이 저장소의 문서와 너의 기본 규칙이 충돌하면 문서를 따른다.
- 작업 전에 다음 인덱스를 읽고, 작업에 맞는 문서를 골라 읽는다: {문서 인덱스 경로}
- 읽을 문서는 위 인덱스가 가리키는 것뿐이다. 그 밖의 `docs/` 문서와 다른 파일에 적힌 문서 링크는 따라가지 않는다.

## 수정 범위

스크립트로 검사한다. 위반하면 되돌린 뒤 다시 호출한다.

- 수정 가능: 입력 파일의 `## 수정 가능 경로`뿐이다.
- 그 밖의 파일은 만들거나 고치거나 지우지 않는다.
- git으로 상태를 바꾸지 않는다(add, commit, restore, checkout, stash, reset 등). status, diff, log만 쓴다.

## 입력 파일

- `_workspace/{NN}_{agent}_input.md`

## 작업 지시

{에이전트별 작업 지시}

## 출력 형식

{공통 출력 + 에이전트별 출력 섹션}
```

## 출력 (에이전트 최종 응답)

섹션 순서와 제목을 고정한다. 해당 내용이 없으면 섹션을 지우지 말고 `없음`이라고 쓴다.

```markdown
## 변경 파일

| 경로     | 변경               | 내용    |
| -------- | ------------------ | ------- |
| `{path}` | 추가 / 수정 / 삭제 | {한 줄} |

## 실행한 명령

| 명령         | 종료 코드 | 결과 요약         |
| ------------ | --------- | ----------------- |
| `{npm test}` | {0}       | {통과 N / 실패 M} |

{에이전트별 섹션}

## 근거

- {판정 근거. `파일:줄` 또는 명령 출력 인용}

판정: {허용 값 하나}
```

- 마지막 줄은 정확히 `판정: {값}`이다. 오케스트레이터는 이 줄만 읽고 다음 단계를 정한다.
- `실행한 명령`에는 `checks.sh` 결과 표를 옮기고, 그 밖에 실행한 명령이 있으면 행을 추가한다.
- 오케스트레이터는 같은 `checks.sh`를 직접 다시 실행해 종료 코드를 대조한다. 다르면 보고서를 받지 않는다.
