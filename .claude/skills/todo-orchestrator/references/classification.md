# 후보 분류 기준

analyst는 이 기준으로 분류하고, 메인 세션은 같은 기준으로 결과를 확인한다. 판정이 어긋나지 않도록 기준은 이 파일에만 둔다. 고칠 때는 이 파일만 고친다.

## 선택 단위

- 독립적으로 시작하고 검증할 수 있는 Issue 하나가 단위다.
- 열린 하위 이슈가 있는 상위 이슈는 후보로 세지 않는다. 하위 이슈로 센다. 같은 작업을 두 번 세지 않기 위해서다.
- 상위 이슈의 본문은 하위 이슈의 순서와 선행 관계를 담는 경우가 많다. 후보가 아니어도 근거 자료로 읽는다.

## 분류

모든 열린 Issue는 아래 중 정확히 하나로 분류한다. 분류 이름만 보고 사용자가 무엇을 하면 풀리는지 알 수 있게 나눈다.

| 분류        | 뜻                                                   | 반드시 함께 쓸 것   |
| ----------- | ---------------------------------------------------- | ------------------- |
| 진행 중     | 진행 흔적이 있고 남은 일이 있다                      | 진행 근거와 남은 일 |
| 시작 가능   | 열린 선행(명시)이 없고 아직 시작 전이다              | 다음 행동           |
| 막힘        | 명시된 선행 Issue가 아직 열려 있다                   | 기다리는 Issue 번호 |
| 판단 대기   | 사용자 결정이 있어야 진행된다. 목표·완료 조건은 있다 | 필요한 결정         |
| 정의 필요   | 목표나 완료 조건이 없거나 판정할 수 없다             | 빠진 것             |
| 상위 묶음   | 열린 하위 이슈가 있는 상위 이슈                      | 하위 번호           |
| 상세 미검토 | 상한 때문에 본문을 읽지 않았다                       | 없음. 제목만        |

## 근거

- **진행 흔적**: 진행을 적은 댓글, 연결 PR, 담당자. 근거가 없으면 진행 중으로 두지 않는다.
- **로컬 근거**: worktree·브랜치의 변경은 브랜치 이름이나 변경 내용으로 Issue와 연결이 확인될 때만 쓰고 "로컬 근거"라고 표시한다. 다른 기기·세션에서는 보이지 않는 근거라 GitHub 근거와 구분한다. Issue와 연결되지 않은 worktree는 보고하지 않는다.
- 모든 근거는 `#번호 "본문·댓글에서 인용한 문장"` 꼴로 쓴다. 메인 세션이 Issue를 다시 열지 않고 확인할 수 있게 하기 위해서다.
- 근거 없는 상태를 지어내지 않는다. 확인하지 못했으면 "미확인"으로 쓴다.

## 선행

| 종류 | 뜻                                                                   | 쓰는 곳                                |
| ---- | -------------------------------------------------------------------- | -------------------------------------- |
| 명시 | 본문·댓글(상위 이슈 포함)에 "~가 닫힌 뒤 시작", 순서도처럼 적혀 있다 | 막힘 판정, 선행 사슬                   |
| 추정 | 코드·이름 의존(예: 다른 Issue가 만드는 상수를 쓴다)으로 추론했다     | 참고로만 표시. 막힘 판정에 쓰지 않는다 |

- 선행 Issue의 상태는 반드시 조회해서 확인한다.
- 이미 닫혔거나 완료 조건이 충족된 선행은 풀린 것이다. 막힘 사유로도, 선행 사슬로도 쓰지 않는다.
- "선행이 풀린다"고 쓸 때는 그 Issue에 남은 다른 선행도 함께 쓴다.

## 순서와 양

- 순서: 사용자 지정 우선순위 → 진행 중 → 시작 가능. 같은 분류 안에서 순서를 정했으면 이유를 한 줄로 쓴다.
- 오늘 후보는 하루 작업량(기본 6시간) 안팎에 들어갈 만큼만 올린다. 후보를 너무 많이 올리지 않기 위한 대략의 기준이다. Issue마다 시간을 매기거나 더하지 않고, 하루 안에 끝낼 수 있는지도 판단하지 않는다.
- 오늘 후보에 넣지 않은 시작 가능 Issue는 "그 외"로 번호와 제목만 남긴다. 후보 수를 강제하지 않고 일부를 전체처럼 말하지 않기 위해서다.

## 묶기

근거가 있는 관계만 쓴다. 주제가 비슷하다는 이유로 묶지 않는다.

- **상위 묶음**: GitHub 상위·하위 관계. `#21 → #22, #23`
- **선행 사슬**: 아직 열린 명시 선행만. `#26 → #23 → #25`
- **독립**: 위 둘에 걸리지 않는다

후보마다 "끝내면 풀리는 Issue"를 쓴다. 명시 선행이 모두 풀리는 Issue만 쓴다.
