# 0005. 스타일 관리. 토큰 계약과 출구 가드레일

## Status

채택

## Context

슬라이스(챌린지)마다 디자인 체계가 다르지만 shadcn/ui 부품과 Tailwind 유틸리티는 같은 토큰 이름을 읽는다. AI가 흐름을 벗어나 쓴 스타일 코드는 문서를 읽지 않으면 검출되지 않았고, 규칙이 의도보다 넓게 정해져 흐름에 통로가 더 생기기도 했다. 이 결정은 스타일 영역에서 [0003](0003-criteria-config-and-verification-code-first.md)이 코드로 올리는 기준의 범위를 흐름의 출구로 좁힌다 (출처: Issue #180, Issue #181, 사용자 확인).

## Decision

- 전역 스타일은 토큰 이름의 계약만 정하고, 슬라이스 값은 `theme.css`에서만 정하며, 검사는 계약을 깨거나 정해진 통로 밖으로 나가는 지점에만 둔다.

- 슬라이스마다 독립된 스타일을 AI가 일관되게 쓰게 하는 문제를 해결해야 했다.
  토큰 계약과 출구 가드레일을 택하고 중앙 값 하향과 단계별 규칙 검사, 정해진 결정 전부 검사는 택하지 않았다.
  검사 대상 축소와 정당한 통로와 출구의 구분을 얻기 위해서이며, 흐름 안 품질의 미보장을 받아들인다.

## Consequences

| 선택지                          | 얻는 것                                     | 잃는 것                        |
| ------------------------------- | ------------------------------------------- | ------------------------------ |
| **토큰 계약과 출구 가드레일**   | 검사 대상 축소<br>정당한 통로와 출구의 구분 | 흐름 안 품질의 미보장          |
| 중앙 값 하향과 단계별 규칙 검사 | 문서 규칙과 검사의 일대일 대응              | 정당한 통로와 출구의 구분 불가 |
| 정해진 결정 전부 검사           | 전부 기계 판정                              | 검사 책임 과다                 |
