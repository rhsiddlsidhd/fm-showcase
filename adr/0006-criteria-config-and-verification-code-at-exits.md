# 0006. 기준 관리. 출구 기준만 코드로

## Status

채택

## Context

[0003](0003-criteria-config-and-verification-code-first.md)의 결정 문장은 판정만 가능하면 불필요한 기준까지 모두 설정이나 검증 코드로 올리라는 뜻으로 읽혔다. 스타일 영역은 [0005](0005-style-management-token-contract-and-exit-guardrails.md)가 범위를 흐름의 출구로 좁혔지만, 다른 영역은 여전히 넓게 읽히는 문장을 따랐다. 이 결정은 0003을 대체하고, 0005는 이 결정을 스타일 영역에 적용한 것이다 (출처: Issue #183, 사용자 확인).

## Decision

- 기계로 판정할 수 있는 기준 중 어기면 정해진 구조·흐름·계약 밖으로 나가는 지점(출구)의 기준만 설정이나 검증 코드로 올리고, 나머지 기준은 이유와 함께 `docs/`에 두어 리뷰가 확인한다.

- 판정할 수 있는 기준 중 무엇을 설정이나 검증 코드로 올릴지 범위를 정하는 문제를 해결해야 했다.
  출구 기준만 코드로를 택하고 판정 가능하면 전부 코드로, 모든 기준을 문서로는 택하지 않았다.
  출구의 결정론적 강제와 검사 대상 축소를 얻기 위해서이며, 흐름 안 품질의 미보장과 설정·검증 코드 유지 비용을 받아들인다.

## Consequences

| 선택지                    | 얻는 것                                | 잃는 것                                           |
| ------------------------- | -------------------------------------- | ------------------------------------------------- |
| **출구 기준만 코드로**    | 출구의 결정론적 강제<br>검사 대상 축소 | 흐름 안 품질의 미보장<br>설정·검증 코드 유지 비용 |
| 판정 가능하면 전부 코드로 | 전부 기계 판정                         | 검사 책임 과다<br>불필요한 규칙 증가              |
| 모든 기준을 문서로        | 낮은 작성 비용                         | 준수 여부 판정 불가                               |
