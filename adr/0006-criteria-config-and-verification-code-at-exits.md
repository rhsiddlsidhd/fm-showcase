# 0006. 기준 관리. 출구 기준만 코드로

## Status

채택

## Context

[0003](0003-criteria-config-and-verification-code-first.md)의 결정 문장은 판정만 가능하면 불필요한 기준까지 모두 설정이나 검증 코드로 올리라는 뜻으로 읽혔고, [0005](0005-style-management-token-contract-and-exit-guardrails.md)가 스타일 영역에서만 그 범위를 흐름의 출구로 좁혔다. 0005에서 출구가 분명했던 것은 토큰 계약, `theme.css`, 정해진 통로가 문서로 먼저 정의돼 있었기 때문이다. 이 결정은 0003을 대체하며, 이미 코드로 올린 기준은 되돌리지 않는다 (출처: Issue #183, 사용자 확인).

## Decision

- 기계로 판정할 수 있는 기준 중 문서에 정한 흐름의 통로 밖으로 나가는지를 묻는 기준만 설정이나 검증 코드로 올리고, 통로 안에서 어떻게 썼는지를 묻는 기준은 이유와 함께 `docs/`에 두어 리뷰가 확인한다.

- 판정할 수 있는 기준 중 무엇을 설정이나 검증 코드로 올릴지 범위를 정하는 문제를 해결해야 했다.
  출구 기준만 코드로를 택하고 판정 가능하면 전부 코드로, 모든 기준을 문서로는 택하지 않았다.
  출구의 결정론적 강제와 검사 대상 축소를 얻기 위해서이며, 흐름 안 품질의 미보장과 설정·검증 코드 유지 비용을 받아들인다.

## Consequences

| 선택지                    | 얻는 것                                | 잃는 것                                           |
| ------------------------- | -------------------------------------- | ------------------------------------------------- |
| **출구 기준만 코드로**    | 출구의 결정론적 강제<br>검사 대상 축소 | 흐름 안 품질의 미보장<br>설정·검증 코드 유지 비용 |
| 판정 가능하면 전부 코드로 | 전부 기계 판정                         | 검사 책임 과다<br>불필요한 규칙 증가              |
| 모든 기준을 문서로        | 낮은 작성 비용                         | 준수 여부 판정 불가                               |
